## 1. 프레임워크란 무엇인가

1. 소프트웨어 프레임워크는 애플리케이션 개발 구조를 재공하는 재사용 가능한 소프트웨어 구성 요소의 집합이다. 개발자가 미리 정의된 구조, 규칙 및 가이드라인을 포함하므로 처음부터 구성할 필요성을 줄이고 효율적인 개발을 가능하게 한다.
2. 프레임워크는 일반적으로 입출력 처리, 데이터베이스 상호작용, 사용자 인터페이스 렌더링, 네트워킹 등과 같은 공통 기능을 추상화하여 개발 프로세스를 단순화하는 라이브러리, 도구, API(애플리케이션 프로그래밍 인터페이스)의 조합을 제공한다.
3. 프레임워크를 활용하면 개발자는 애플리케이션의 특정 비즈니스 로직을 구현하는데 집중할 수 있다.

다양한 프로그래밍 언어, 플랫폼, 도메인에 맞춰 다양한 형태로 제공된다. 소프트웨어 프레임워크를 사용하면 생산성 향상, 코드 재사용성, 일관성, 유지 관리성, 확장성 등의 이점을 얻을 수 있다. 프레임워크는 모법사례, 디자인 패턴, 아키텍쳐 원칙을 따르므로, 구조화되고 모듈화되며 테스트 가능한 소프트웨어를 더 쉽게 만들 수 있다. + 문서 지원, 대규모 커뮤니티도 지원하는 경우도 다수 있다.

유의할 점 : 학습 곡선을 초래, 제약이나 한계가 초래될 수 있다. → 특정 프레임워크의 목적, 기능 및 한계를 이해하는 것이 중요하다.

## 2. 소프트웨어 프레임워크의 기원

소프트웨어 프레임워크라는 개념은 1960년대 후반~1970년대 초반 소프트웨어 개발의 복잡성 증가에 대한 대응책으로 등장하였다. 이 시기에 프로그래머들은 개발 프로세스를 간소화하고 코드 재사용을 촉진할 수 있는 재사용 가능하고, 표준화된 컴포넌트의 필요성을 깨달았다.

1. 소프트웨어 프레임워크의 선구자 중 한명은 더글러스 C.엥겔바트이다. 그는 1960년대 NLS(oN-Line System)를 개발했다. NLS는 대화형 애플리케이션을 만들고, 정보를 구성하기 위한 도구와 구성 요소 세트를 제공해서 프레임워크의 가장 초기 사례 중 하나로 간주될 수 있다.

1. 또 다른 소프트웨어 프레임워크의 선구자는 제록스 팔로알토 연구센터이다. 팔로알토 연구센터에서 개발한 스몰토크 프로그래밍 언어는 객체와 클래스의 개념을 도입하여 객체 지향 프로그래밍(OOP)의 기반을 마련했다. 스몰토크 또한 MVC 아키텍쳐 패턴을 통합했는데, 이후 여러 소프트웨어 프레임워크의 기반이 되었다.

1980년대 GUI의 등장은 소프트웨어 프레임워크 개발을 더욱 가속화 했다. MacApp과 같은 객체지향 GUI 프레임워크는 개발자에게 사용자 인터페이스를 구축할 수 있는 재사용 가능한 컴포넌트와 라이브러리 세트를 제공했다.

오픈소스는 소프트웨어 프레임워크의 발전과 확산에 중요한 역할을 했다. 오픈소스 프레임워크의 등장으로 개발자들은 프레임워크의 활용 뿐만 아니라 개선 및 맞춤 설정에도 기여할 수 있게 되었다

## 3. 프레임워크와 아키텍쳐 차이점

소프트웨어 프레임워크와 소프트웨어 아키텍쳐는 관련된 개념이지만, 차이점이 존재한다.

### 소프트웨어 프레임워크

소프트웨어 프레임워크는 공통 기능을 추상화하여 개발 프로세스를 단순화하는 일련의 사전 정의된 규칙, 지침, 라이브러리 및 도구를 통해 **애플리케이션 개발을 위한 구조를 제공**한다.

프레임워크는 재사용 가능한 구성 요소를 제공하고, 개발자가 특정 애플리케이션 요구사항에 맞춰 개발할 수 있는 규칙을 수립한다. 프레임워크의 주요 목표는 **표준화된 구조**를 제공하고, **코드 재사용을 촉진**하여 생산성과 유지 관리성을 향상하는 것이다.

### 소프트웨어 아키텍쳐

소프트웨어 아키텍쳐는 소프트웨어 시스템이나 애플리케이션의 **전반적인 구조와 구성을 정의**한다. 여기서 애플리케이션의 개발 및 배포를 안내하는 고수준의 **설계, 원칙, 패턴**이 포함된다.

시스템 확장성, 성능, 보안, 안정성, 유지보수성과 같은 전략적 문제에 중점을 둔다. 그리고 다양한 구성 요소 또는 모듈 간의 관계, 데이터 흐름, 그리고 애플리케이션 내 다양한 시스템 간의 상호작용을 간략하게 설명한다.

### 결론(차이점)

1. 소프트웨어 프레임워크가 **특정 구조와** **미리 정의된 기능을 제공**하는 반면, 소프트웨어 아키텍쳐는 전체 시스템이 어떻게 구성되고 운영하는지를 보다 광범위한 **전략적 설계 및 의사결정 프로세스**이다.

1. 소프트웨어 아키텍쳐는 시스템 전반적인 목표와 요구사항, 그리고 구성 요소들의 상호작용 방식을 고려한다. 반면 소프트웨어 프레임워크는 미리 정의된 구조 내에서 개발 프로세스를 용이하게 하는 구체적인 구현이다.

프레임워크가 아키텍쳐의 일부가 될 수 있다.

## 4. 9가지 유형의 프레임워크

1. 웹 애플리케이션 프레임워크

   웹 애플리케이션 개발을 간소화하도록 설계하였다. 예) 데이터베이스 통합, 세션관리, 사용자 인증 등의 기능을 포함한다.

2. 모바일 애플리케이션 프레임워크

   iOS, Android와 같은 여러 플랫폼에서 실행되는 애플리케이션을 개발할 수 있다. 사용자 인터페이스를 구축하고, 기기별 기능을 처리하고, 네이티브 기기 API에 접근할 수 있는 도구를 제공한다.

3. 프론트엔드 프레임워크

   웹 애플리케이션의 클라이언트 측 개발에 중점을 주며 UI구성 요소와 상호작용을 다룬다. 반응형이고 시작적으로 매력적인 인터페이스를 구축하기 위한 라이브러리, 템플릿, 유틸리티를 제공한다.

4. 백엔드 프레임워크

   서버 측 개발에 사용되며, 요청처리, 데이터베이스 통합, 비즈니스 로직 구현 등을 처리한다. 개발 프로세스를 간소화하는 추상화와 도구가 함께 제공된다.

5. 테스트 프레임워크

   애플리케이션의 테스트 프로세스를 자동화하여 코드의 신뢰성과 정확성을 보장한다. 예를 들어 JUnit은 Java 애플리케이션에서 널리 사용되는 테스트 프레임워크로, TDD와 Unit test를 용이하게 한다.

6. 게임 개발 프레임워크

   게임 개발 프레임워크는 다양한 도구와 기능을 통해 비디오 게임 제작을 간소화한다. 게임 물리 엔진, 자산 관리 시스템, 렌더링 기능 등이 포함되어있는 경우가 많다.

7. ML 프레임워크

   머신러닝 프레임워크는 데이터 전처리, 모델 학습 및 배포를 위한 추상화를 통해 머신러닝 모델을 개발하는데 필요한 알고리즘, 도구 및 라이브러리를 제공한다. 텐서플로우는 딥러닝, 신경망 및 분산 컴퓨팅을 지원한다.

8. 엔터프라이즈 애플리케이션 프레임워크

   복잡한 기능과 기존 시스템과의 통합을 요구하는 대규모 엔터프라이즈 애플리케이션을 개발하도록 설계되었다. 보안, 확장성, 모듈형 아키텍쳐를 위한 기능을 제공한다. 예) JAVA EE

9. GUI 프레임워크

   GUI 프레임워크는 UI 구성 요소를 디자인하고, 사용자 입력을 처리하고, 이벤트를 관리하는 도구를 제공하여 데스크톱 또는 모바일 애플리케이션의 GUI 제작을 간소화한다.

## 5. 프레임워크의 중요성 : 8가지 주요 이점

### 1. 효율성과 속도 향상

개발 속도를 크게 높여주는 미리 작송된 코드 라이브러리, 템플릿, 도구를 제공한다. 모든 것을 직접 처음부터 개발할 필요가 없으므로 애플리케이션 별 기능과 비즈니스 로직에 집중할 수 있다.

### 2. 모범 사례를 통한 일관성 유지

확립된 디자인 패턴과 모범 사례를 따르는 경우가 많아 일관되고 유지 관리가 용이한 코드베이스를 보장한다. 구조화된 접근 방식을 제공하여 코드 구성, 공통 작업 처리, 모듈형 아키텍쳐 유지를 위한 지침을 제공한다.

### 3. 용이한 추상화와 단순화

복잡한 기능과 기술적 세부사항을 추상화하여 개발자에게 고수준 인터페이스를 제공한다. 하위 수준의 구현 세부 사항을 깊이 파고들지 않고도 프레임워크의 기본 기능을 활용할 수 있다.

### 4. 신속한 프로토타입 제작 지원

즉시  사용가능한 컴포넌트와 기능을 제공하여 신속한 프로토타입 제작을 용이하게 한다. 신속한 프로토타입 구축 → 아이디어 검증 → 이해관계자나 사용자의 피드백을 수집할 수 있다.

### 5. 커뮤니티 및 생태계

인기 프레임워크는 규모가 크고 활발한 개발자 커뮤니티를 보유하고 있는 경우가 많다. 광범위한 문서, 튜토리얼, 포럼, 그리고 오픈소스 기여를 활용할 수 있다.

### 6. 보안 및 안정성 강화

일반적인 취약점으로 부터 보호하는데 도움이 되는 보안 조치와 모범 사례가 내장되어있는 경우가 많다. 정기적인 업데이트와 개선을 통해 모든 보안 패치나 버그 수정이 신속하게 적용된다.

### 7. 확장성과 유연성을 위한 길

많은 프레임워크는 확장성과 유연성을 염두에 두고 설계되었다. 데이터베이스 추상화 계층, 캐싱 매커니즘, 부하 분산 지원과 같은 기능을 적용하여 트래픽 증가나 요구사항 변경을 처리하는데 도움을 준다.

### 8. 상호 운용성을 위한 산업 표준

널리 채택된 프레임워크를 사용하면 업계 준수를 보장하고 상호 운용성을 향상시킬 수 있다. 많은 프레임워크가 다양한 기술과 프로토콜을 기본적으로 지원하므로, 기존 시스템이나 타사 API와의 통합이 쉬워진다.

## 6. Next.js 프레임워크란

Next.js는 풀스택 웹 애플리케이션을 구축하기 위한 React 기반 프레임워크이다. 프론트엔드의 UI는 React로 구성하며, Next.js는 페이지 라우팅, 서버사이드 렌더링, 정적 사이트 생성 및 성능 최적화와 같은 기능을 제공한다. 또한 Next.js는 번들링, 컴파일 등의 작업을 추상화하고 자동으로 처리해 개발자가 설정에 많은 시간을 들이지 않고 애플리케이션 개발에 집중할 수 있도록 돕는다.

특히 Next.js는 React를 보다 강력하고 편리하게 사용할 수 있는 다양한 기능을 제공한다.

- Page Routing : 별도의 설정 없이 간단하게 페이지 간 이동을 구현할 수 있다.
- 빌트인 성능 최적화 : Next.js는 자동으로 성능을 최적화하여 빠른 페이지 로딩을 지원한다.
- 동적 HTML 스트리밍 : 서버에서 HTML을 스트리밍하여 더 빠르게 콘텐츠를 전달한다.

## 7. Next.js의 탄생 과정

현재 까지 많이 사용되고 있는 라이브러리는 React이다. 이유는 CSR을 통해 SPA를 구축하는 라이브러리로, 페이지의 전환 없이 한 페이지에서 바뀐 부분에 대해서만 화면 전환이 이루어지기 때문에, 사용자 경험을 향상시키는데 유리하기 때문이다.

React의 단점으로 CSR이기 때문에 HTML을 처음부터 바로 보내주는게 아닌, 빈 HTML을 보여주고 그 다음에 필요한 Resource를 다운받기에, 초기 로딩 속도가 느리고 FCP가 SSR에 비해 느리다. 또 검색 엔진 최적화 측면에서 불리하다.

이러한 문제를 해결하기 위해 React에서 SSR의 렌더링 방식을 보완하게 된 프레임워크가 Next.js이다.

## 8. Next.js의 특징

### 사전 렌더링 및 서버사이드 렌더링

Next.js는 빌드 시 Page Router 기준 : `Static` → 빌드 시 렌더링, `SSR` → 요청 시 렌더링, `CSR` → 클라이언트에서 렌더링을 하며 App Router 기준 : `Static` 렌더링(기본 값) → 빌드 시 렌더링(HTML 생성), `동적` 렌더링 → 요청 시 SSR(서버에서 HTML 생성), `ISR` → 정적 생성이지만 일정 주기로 재생성, CSR → 클라이언트에서 렌더링을 한다.
