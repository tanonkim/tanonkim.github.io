사이트와 앱이 제대로 작동하지 않으면 사용자에게 눈에 띄기에 렌더링 성능을 최적화하는 것이 중요하다.

오늘날 방문하는 페이지가 원활하고 쌍방향적이길 원한다. 따라서 페이지는 빠르게 로드되는 것과 전체 생명 주기동안 사용자의 입력에 빠르게 응답해야 한다.

사용자 환경은 INP(Interaction to Next Page)에서 정확하게 측정한다. INP가 우수하다는 의미는 페이지가 사용자의 입력에 일관되게 빠르게 반응했다는 의미이다.

**사용자 인터페이스**

페이지가 빠르게 느껴지는 주요 요소로 사용자 상호작용에 대한 응답으로 실행하는 JS가 포함되지만, 사용자가 기대하는 것은 사용자 인터페이스의 시각적 변경사항이다. 사용자 인터페이스의 시각적 변경사항은 여러 유형의 작업의 결과이며, 이러한 작업은 `렌더링`이라고 통칭된다. 렌더링은 사용자 환경이 빠르고 안정적으로 느껴지도록 최대한 빨리 이루어져야 한다.

사용자 상호환경에 빠르게 응답하는 페이지를 작성하기 위해선 브라우저에서 HTML, JS, CSS가 처리되는 방식을 이해하고, 다른 서드파티 코드가 최대한 효율적으로 실행되도록 해야 한다.

## 기기 새로고침 빈도에 관한 참고사항

오늘날 대부분의 기기는 화면을 초당 60번 새로고침한다. 60프레임이라고 한다.

기기의 화면은 일정한 속도로 새로고침되지만, 기기에서 실행되는 애플리케이션은 항상 충분한 프레임을 생성하지 못할 수 있다. 일반적은 디스플레이가 초당 60번 새로고침된다면 각 브라우저가 프레임을 생성하는데 16.6ms가 걸린다. 하지만 실제로 브라우저에 각 프레임에 대한 오버헤드가 있으므로 모든 작업을 10ms초 이내에 완료해야 한다. 그렇지 못하면 콘텐츠가 화면에서 흔들린다. (버벅거린다고 한다.)

버벅거림을 방지하기 위해 애니메이션에 많은 프레임을 생성하는 것이든, 사용자 인터페이스에서 개별적인 시각적 변화를 최대한 빨리 생성하는 것이든, 브라우저의 `픽셀 파이프라인`이 작동하는 방식을 이해하는 것이 필수적이다.

## 픽셀 파이프라인

아래 5가지 영역은 개발자가 가장 효과적으로 제어할 수 있는 영역이며, 픽셀-화면 파이프라인의 핵심 지점을 나타낸다.

![](/assets/img/2025-04-20/browser-rendering-performance-1.png)

- JavaScript

  자바스크립트는 일반적으로 사용자의 인터페이스의 시각적 변경을 초래하는 작업을 처리하는데 사용된다. jQuery의 animate함수, 데이터 세트 정렬, 페이지에 DOM 요소 추가 등이 해당된다. CSS 애니메이션, CSS 전환 Web Animations API를 사용하면 JS 없이 페이지 콘텐츠를 애니메이션할 수 있다.

- 스타일 계산

  해당되는 선택자를 기반으로 어떤 CSS 규칙이 어떤 HTML요소에 적용되는지 파악한다. .headline은 headline클래스가 포함된 모든 HTML요소에 적용되는 CSS선택자이다. 이런 규칙이 파악되면 규칙이 적용되고, 각 요소의 최종 스타일이 계산된다.

- 레이아웃

  브라우저가 요소에 적용되는 규칙을 알면 요소가 차지하는 공간, 화면에 표시되는 페이지의 도형을 계산할 수 있다.

  웹의 레이아웃 모델은 한 요소가 다른 요소에 영향을 줄 수 있다. 예) `<body>` 요소의 width는 트리 전체에서 하위 요소의 크기에 영향을 주므로 부라우저에서 이 프로세를 처리하는데 상당한 시간이 걸릴 수 있다.

- 페인트

  페인팅은 픽셀을 채우는 프로세스이다. 페이지의 레이아웃이 계산된 후 텍스트, 색상, 이미지, 테두리, 그림자 등 모든 시각적 측면을 그리는 작업이다. 일반적으로 레이어라고 하는 여러 노출 영역에서 이루어진다.

- 합성

  페이지의 일부가 여러 레이어에 그려질 수 있으므로 페이지가 예상대로 렌더링되도록 올바른 순서로 화면에 적용해야 한다.

  다른 요소와 겹치는 요소에 잘못 표시되지 않도록 주의해야 한다.

모든 프레임에서 파이프라인의 모든 부분을 건들일 필요는 없다. 실제로 JS, CSS, Web Animations API를 사용하여 시각적 변경사항을 적용할 때 특정 프레임에 일반적으로 적용되는 방법 3가지가 있다.

1. JS/CSS > 스타일 > 레이아웃 > 페인트 > 합성

   left, top 속성, 즉 너비/높이/위치와 같은 도형을 변경하는 레이아웃 속성을 변경하면 브라우저는 다른 모든 요소를 확인하고 페이지를 다시 처리해야 한다. 영향을 받는 영역은 다시 페인트를 해야 하며, 최종적으로 페인트된 요소는 다시 합성해야 한다.

2. JS/CSS > 스타일 > ~~레이아웃~~ > 페인트 > 합성

   페인트 전용 속성 : background-image, color, box-shadow와 같은 속성을 변경한 경우 레아아웃 단계가 필요없다. 레이아웃단계를 생략하면 비용이 많이 드는 레이아웃 작업을 방지할 수 있다.

3. JS/CSS > 스타일 > ~~레이아웃~~ > ~~페인트~~ > 합성

   레이아웃이나 페인트가 필요하지 않은 속성을 변경하면 바로 합성(컴포지션) 단계로 이동가능하다.

## 브라우저 렌더링 최적화

성능은 사용자에게 중요하다. 우수한 사용자 환경을 사용하려면 웹개발자가 사용자 상호작용에 빠르게 반응하고 원활하게 렌더링되는 웹사이트를 빌드해야 한다.

목표 : 초당 60프레임을 유지하는 웹/앱을 만들자. 이 과정을 거치면 애플리케이션을 프로파일링하고 최적화되지 않은 렌더링의 성능의 원인을 파악하는데 필요한 도구를 갖게 된다.
