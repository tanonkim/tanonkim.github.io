### 4. 콜백 함수

콜백함수 : 다른 코드의 인자로 넘겨주는 함수

다른 코드에게 인자로 넘겨줌으로써 그 제어권도 함께 위임한 함수

### section2 제어권

### 2.1 호출 시점

```jsx
var count = 0;
var timer = setInterval(() => {
    console.log(count);
    if (++count > 4) {
        clearInterval(timer);
    }
}, 300);
```

scope에는 window 객체 또는 worker의 인스턴스가 들어올 수 있음. 두 객체 모두 setInterval 메서드를 제공함.

```jsx
var count = 0;
var cbFunc = function () {
    console.log(count);
    if (++count > 4) clearInterval(timer);
};

var timer = setInterval(cbFunc, 300)
```

| code | 호출 주체 | 제어권 |
| --- | --- | --- |
| cbFunc() | 사용자 | 사용자 |
| setInterval(cbFunc, 3000) | setInterval | setInterval |

⇒ 콜백 함수의 제어권을 넘겨받은 코드는 콜백 함수 호출 시점에 대한 제어권을 가짐

### 2.2 인자

```jsx
var newArr = [10, 20, 30].map(function (currentValue, index) {
    console.log(currentValue, index);
    return currentValue + 5;
});

console.log(newArr); // [15,25,35]
```

참고) map 메서드의 구조

```jsx
Array.prototype.map(callback[, thisArg])
callback : function(currentValue, index, array)
```

첫번째 인자 : callback함수, 

두번째 인자 : 콜백함수 내부에서 this로 인식할 대상 (생략 가능)

### 2.3 This

콜백 함수도 함수이기에 기본적으로는 this가 전역객체를 참조함.

제어권을 넘겨받을 코드에서 콜백함수에 별도로 this가 될 대상을 지정 → 그 대상을 참조하게 됨

```jsx
Array.prototype.map = function (callback, thisArg) {
    var mappedArr = [];
    for (let i = 0; i < this.length; i++) {
        var mappedValue = callback.call(thisArg || window, this[i], i, this);
        mappedArr[i] = mappedValue;
    }
    return mappedArr;
};

```

this : thisArg값이 있는 경우 그 값을, 없는 경우 전역 객체

⇒ 제어권을 넘겨받을 코드에서 call/apply 메서드의 첫 번째 인자에 콜백 함수 내부에서의 this가 될 대상을 명시적으로 바인딩함.

```jsx
setTimeout(() => {
    console.log(this); // (1) window
}, 300);

[1, 2, 3, 4, 5].forEach(function (x) {
    console.log(this); // (2) window
});

document.body.innerHTML += '<button id="a">Click</button>';
document.body.querySelector('#a').addEventListener('click', function (e) {
    console.log(this, e); // <button id="a">클릭</button>,즉 HTML element
});
```

(1) setTimeout : 콜백 함수를 호출할 때 call메서드의 첫번째 인자에 전역객체를 넘김 → 콜백함수 내에서 this가 전역객체를 가리킴

(2) forEach : 별도의 인자로 this를 받는 경우, 별도의 인자로 this를 넘겨주지 않음 → 전역객체

(3) addEventListener : call 메서드의 첫번째 인자에 메서드의 this를 그대로 넘기도록 정의

### secton3 콜백함수는 함수다

콜백함수로 어떤 객체의 메서드를 전달하더라도, 그 메서드는 함수로서 호출됨

```jsx
var obj = {
    vals: [1, 2, 3],
    logValues: function (v, i) {
        console.log(this, v, i); 
    },
};

obj.logValues(1, 2);              // obj 1 2
[4, 5, 6].forEach(obj.logValues); // Window 4 0
																	// Window 5 1
																	// Window 6 2
```

obj.logValues : 메서드로서 호출 → this는 obj

forEach 메서드에 obj.logValues를 콜백함수로 전달하면 this가 obj가 아닌 전역객체를 가리킴

### section4 콜백 함수 내부의 this에 다른 값 바인딩하기

객체의 메서드를 콜백함수로 전달한다면 해당 객체를 this로 바라볼 수 없게 됨

별도의 인자로 this를 받는 함수 : 원하는 this를 넘겨주면 됨

그렇지 않은 경우 : this의 제어권도 넘겨줌 → 사용자가 임의로 값을 바꿀 수 없음

⇒ 해결책 : this를 다른 변수에 담아 콜백 함수로 활용할 함수에서 this대신 변수 사용, 클로저를 만듬

예시1) 전통적인 방식

```jsx
var obj = {
    name: 'obj1',
    func: function () {
        var self = this;
        return function () {
            console.log(self.name);
        };
    },
};

var callback = obj.func();
setTimeout(callback, 1000);
```

너무 번거로움

예시2) 콜백 함수 내부에서 this를 사용하지 않은 경우

```jsx
var obj1 = {
    name: 'obj1',
    func: function () {
        console.log(obj1.name);
    },
};

setTimeout(obj1.func, 1000);
```

간결하지만 this를 이용해 다양한 상황에서 재사용이 불가능해짐

예시3) func함수의 재활용 _ 해결책

```jsx
var obj2 = {
    name: 'obj2',
    func: obj1.func,
};

var callback2 = obj2.func;
setTimeout(callback2, 1500);
// bind메서드 활용 
setTimeout(obj1.func.bind(obj1), 1500)

// call메서드 활용
var obj3 = { name: 'obj3' };
var callback3 = obj1.func.call(obj3);
setTimeout(callback3, 2000);
```

callback2에는 obj2의 func를 실행한 결과를 담아 콜백으로 사용.

callback3에는 obj1의 func를 실행하면서 this를 obj3로 지정해 콜백으로 사용

### section5 콜백 지옥과 비동기 제어

콜백지옥 : 콜백 함수를 익명함수로 전달하는 과정에서 **반복**되어 코드의 **들여쓰기 기준**이 감당하기 어려운 정도로 깊어지는 현상

- 동기 : 실행중인 코드가 완료된 후에 다음 코드를 실행하는 방식
- 비동기 : 현재 실행중인 코드의 완료여부와 무관하게 즉시 다음 코드로 넘어감

별도의 요청, 실행대기, 보류 등 관련된 코드는 비동기적인 코드

예) setTimeout, addEventListener, XMLHttpRequest

예시1) 콜백지옥 예시

```jsx
setTimeout(
  function (name) {
    var coffeeList = name;
    console.log(coffeeList);

    setTimeout(
      function (name) {
        coffeeList += ", " + name;
        console.log(coffeeList);

        setTimeout(
          function (name) {
            coffeeList += ", " + name;
            console.log(coffeeList);

            setTimeout(
              function (name) {
                coffeeList += ", " + name;
                console.log(coffeeList);
              },
              500,
              "카페라떼"
            );
          },
          500,
          "카페모카"
        );
      },
      500,
      "아메리카노"
    );
  },
  500,
  "에스프레소"
);

//"에스프레소"
//"에스프레소", "아메리카노"
//"에스프레소", "아메리카노", "카페모카"
//"에스프레소", "아메리카노", "카페모카", "카페라떼"
```

예시2) 콜백지옥 해결 : 기명함수로 전환

예시3) 비동기 작업의 동기적 표현 _ Promise

JS에서는 비동기적인 작업을 동기적으로, 동기적으로 보이게끔 하는 노력을 함 

ES6 : Promise, Generator

ES2017 : async/await

```jsx
new Promise(function (resolve) {
    setTimeout(() => {
        var name = 'espresso';
        console.log(name);
        resolve(name);
    }, 500);
}).then(function (prevName) {
    return new Promise(function (resolve) {
        setTimeout(() => {
            var name = prevName + ', cafeMoca';
            console.log(name);
            resolve(name); // resolve or reject
        }, 500);
    });
}) ... chaning
```
