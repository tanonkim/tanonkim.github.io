## 1. 트랜잭션 정의

데이터베이스 시스템에서의 상호작용 단위.

시스템 : 트랜잭션이 성공과 실패가 분명하고 상호 독립적이며, 일관되고 믿을 수 있는 시스템이다. 데이터의 정합성을 보장하기 위해 고안된 방법이다.

### 트랜잭션의 목적

에러로부터 복구를 허용하고, 데이터베이스를 일관성있게 유지하는 안정적인 단위를 제공한다.

동시에 접근하는 여러 프로그램 간 격리를 제공한다.

## 2. ACID

이론적으로 데이터베이스 시스템은 각각 트랜잭션에 대해 ACID를 보장한다.

### Atomic

트랜잭션이 완전히 성공하거나 완전히 실패하는 단일 단위로 처리되도록 보장하는 능력 → 중간단계까지 실행하고 실패하는 경우가 없도록 함

### Consistency

각 데이터 트랜잭션이 데이터베이스를 일관성있는 상태에서 일관성있는 상태로 유지해야 함을 의미. → 트랜잭션이 성공적으로 완료하면 언제나 동일한 데이터베이스 상태로 유지

### Isolation

트랜잭션을 수행 시 다른 트랜잭션의 연산 작업이 끼어들지 못하도록 보장하는 것을 의미 → 트랜잭션 밖에 있는 어떤 연산도 중간 단계의 데이터를 볼 수 없다.

### Durability

성공적으로 수행된 트랜잭션은 영원히 반영되어야 한다. → 데이터베이스 내의 데이터는 트랜잭션의 결과로만 반영되어야 하며, 외부 영향에 의해 변경되지 않아야 한다. + 트랜잭션은 로그에 모든 것이 저장된 이후에만 commit 상태로 간주될 수 있다.

## 3. 트랜잭션 과정

1. 트랜잭션 시작
2. 비즈니스 로직 실행 (여러 쿼리 실행 O, DB 내 적용 X)
3. 트랜잭션 커밋 (갱신이 실제 적용)

만약 쿼리 하나라도 실패하면 데이터베이스 시스템은 해당 트랜잭션 또는 실패한 쿼리를 롤백한다.

### 4. Transacional Database

트랜잭션을 지원하는 데이터베이스를 Transactional Database로 부른다. 현재 대부분의 RDBMS는 Transactional Database이다.

## 4. @Transactional (선언적 트랜잭션)

### 개념

소스코드에 직접 트랜잭션 로직을 넣어두지 않고 비즈니스 로직에서 완전히 분리하는 방식이다. → 트랜잭션 코드 중복, 유지보수 문제를 해결할 수 있다.

### 구현방식

Spring에서는 AOP를 사용해서 @Transactional을 구현하고 있다.

1. `AbstractPlatformTransactionManager`에서 팩토리 메서드 패턴을 사용해서 여러 `PlatformTransactionManager`을 확장한다
1. `TransactionInterceptor` 를 통해 트랜잭션 경계를 설정하고 여기에서 주입 된 `PlatformTransactionManager` 를 사용한다.
2. `pringTransactionAnnotationParser` 를 통해 `@Transactional` 관련 속성을 파싱한다.
3. `AbstractAutoProxyCreator` 에 의해 `Proxy`로 생성되고 실제 클라이언트가 타깃에 접근할때는 `Proxy`를 거쳐 `TransactionInterceptor` 를 사용해 트랜잭션을 열고타깃의 메서드를 호출하고 커밋, 롤백을 수행한다.

### Transaction의 격리수준

1. Default : 데이터베이스에서 설정된 기본 격리 수준
2. READ_UNCOMMITED : 트랜잭션이 아직 커밋되지 않은 데이터를 읽을 수 있다.
3. READ_COMMITED : Dirty Read를 방지하기 위해 Commit된 데이터만 읽을 수 있다.
4. REPETABLE_READ : 트랜잭션이 완료될 때까지 조회한 모든 데이터에 shared lock이 걸린다. 트랜잭션이 종료될 때까지 다른 트랜잭션은 그 영역에 해당하는 데이터를 수정할 수 없다.
5. SERIALIZABLE

   가장 엄격한 트랜잭션 격리수준이다. 완벽한 읽기 일관성 모드를 제공하며, 격리 수준에서는 PHANTOM READ상태가 발생하지 않지만 동시성 처리 성능이 급격히 떨어질 수 있다.

### Transaction 전파(Propagation)

1. REQUIRED : 이미 시작된 트랜잭션이 있으면 참여하고, 없으면 새로운 트랜잭션을 시작한다. (default)
2. SUPPORTS : 이미 시작된 트랜잭션이 있으면 참여하고, 없으면 트랜잭션 없이 처리한다.
3. REQUIRED_NEW : 항상 새로운 트랜잭션을 시작한다. 이미 진행중인 트랜잭션이 있다면 잠시 보류시킨다.
4. MANDATORY : 이미 시작된 트랜잭션이 있으면 참여하고, 없으면 새로운 트랜잭션을 시작하는 대신 예외를 발생한다. (혼자서 독립적으로 수행되면 안되는 경우 사용됨)
5. NOT_SUPPORTED : 트랜잭션을 사용하지 않고 처리하도록 한다. 이미 진행중인 트랜잭션이 있다면 잠시 보류시킨다.
6. NEVER : 트랜잭션을 사용하지 않도록 강제한다.
7. NESTED : 이미 실행중인 트랜잭션이 있다면 중첩하여 트랜잭션을 진행한다. 부모 트랜잭션은 중첩 트랜잭션에 영향을 준다. ↔ 중첩 트랜잭션은 부모 트랜잭션에 영향을 주지 않는다.

### readOnly 옵션

`readOnly` 속성을 통해 트랜잭션을 읽기 전용으로 설정할 수 있다.

JPA의 경우 트랜잭션이 commit되어도 flush하지 않는다. → 엔티티 스냅샷 비교 로직이 수행되지 않아서 성능이 약간 향상될 수 있다.
