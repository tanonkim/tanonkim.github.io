객체지향 프로그래밍에서는 현실세계에서 관찰해 배운 지식들을 모델에 반영하고, 시간이 지나면서 계속 변화하는 모델을 구축한다. 그러나 통제할 수 없을 수준까지 변경하거나, 남용해서 불완전한 표현을 생성하고, 변경 사항으로 인한 파급 효과 때문에 중요한 설계 원칙을 위반하는 결과를 초래할 수 있다.

함수형 패러다임에서는 이 변화를 금지하는 방법으로 문제를 해결한다.

- 가변성에 대한 다른 접근 방식
  1. 객체는 생성 시 완전해야 한다.
  2. 세터가 존재하면 안된다.
  3. 게터가 존재하면 안된다. get() 책임이 객체 동작의 일부가 아니다.

### var를 const로 변경하기

문제 : var로 선언된 변수가 있다.

→ 변수이름, 범위 및 가변성을 현명하게 선택하기.

예) 올바르지 않은 접근방식

```javascript
var pi = 3.14
var universeAgeInYears = 13800000000

pi = 3.1415 // 오류 없음
universeAgeInYears = 138000000001 // 오류 없음
```

예) 올바른 접근 방식

```javascript
const pi = 3.14
const universeAgeInYears = 13800000000

pi = 3.1415 // 오류
universeAgeInYears = 138000000001 // 오류
```

### 변수를 가변적이게 선언하기

문제 : 변수에 값을 할당하고 사용하지만 절대 변경하지 않는다.

→ 프로그래밍 언어에서 허용하는 경우 가변적인 선택자 이용

예) 변수로 설정된 비밀번호

```php
function configureUser() {
	$password = '123456';
	user = new User($password);
}
```

예) 상수로 선언된 비밀번호

```php
define ("USER_PASSWORD", '123456');

function configureUser() {
	$user = new User(USER_PASSWORD);
}
```

### 본질 변경 금지하기

문제 : 객체의 본질이 변형된다.

→ 필수 속성이 설정된 후에는 변경 금지하기

예) 객체의 본질을 변형

```javascript
const date = new Date();
date.setMomnth(4);
```

Date는 원래 mutable하게 설계되었다. date.setMonth(4)를 하면 내부 값이 바뀌는게 기본 동작이지만, 불변성 유지라는 원칙에 맞지 않다. → 그래서 date-fns, dayjs, luxon같은 불변 기반 날짜 라이브러리를 사용한다.

예1) 모든 설정자 제거

```javascript
class Date {
//	setMonth() {
//		this.month = month
//	}
}
```

예2) 라이브러리

```javascript
import { setMonth } from "date-fns";

const date = new Date();       // 2025-09-04
const newDate = setMonth(date, 4);  // 2025-05-04

console.log(date);    // 원본 그대로 2025-09-04
console.log(newDate); // 새로운 객체 2025-05-04
```

### 변경 가능한 상수 배열 피하기

문제 : 배열을 상수로 선언했지만 변경이 가능하다.

→ 언어를 사용할 때 가변성을 주의하고 그 범위를 이해해야 한다.

예) 가변가능한 array

```javascript
const array = [1,2];
array.push(3)
```

예) 조금 더 선언적인 예제

```javascript
const array = [1,2];
const newArray = [...array, 3];
```

array ⇒ [1,2] : 변이되지 않음

newArray = [1,2,3]

참고 : 얕은 복사

### 지연된 초기화 제거하기

문제 : 지연된 초기화를 사용해 비용이 많이 필요한 객체를 필요한 시점에 조회하고, 그 전까지는 지연한다.

→ 지연된 초기화 사용하지 말기, 대신 객체 공급자 사용하기

지연된 초기화는 여러 스레드가 동시에 객체에 접근하고 초기화를 시도할 때 동시성 문제, 경쟁 상태와 같은 여러 문제를 야기할 수 있다.

예) 지연 초기화

```javascript
class Employee {
	constructor () {
		this.emails = null;
		this.voiceMails = null;
	}
	
	getEmails() {
		if (!this.emails) {
			this.emails = [];
		}
		return this.emails;
	}
	
	getVoiceMails() {
		if (!this.voiceMails) {
				this.voiceMails = [];
		}
		return this.voiceMails;
	}
}
```

참고 : 실제로 성능 문제가 있는 경우 싱글턴 패턴 대신 프록시 패턴, 퍼사드 패턴을 사용해야 한다.

예) Proxy 사용

```javascript
class Employee {
	constructor () {
		return new Proxy(this, {
			get(target, prop, receiver) {
				if (prop === 'emails' && target[prop] == null) {
					target[prop] = [];
				}
				if (prop === 'voiceMails' && target[prop] == null) {
					target[prop] = [];
				}
				return Reflect.get(target, prop, receiver);
			}
		});
	}
}
```

### 변경 가능한 상수 고정하기

문제 : const 키워드를 사용해 무언가를 상수로 선언한다. 하지만 상수의 일부를 변경할 수 있다.

→ 불변 상수 사용하기

예) 객체인 상수의 주소값 변경

```javascript
const DISCOUNT_PLATINUM = 0.1;
const DISCOUNT_GOLD = 0.05;
const DISCOUNT_SILVER = 0.02;

const DISCOUNT_SILVER = 0.03 // Error

// -------------------------------------

// Group
const ALL_CONSTANTS = {
	DISCOUNT : {
		PLATINUM = 0.1;
		GOLD = 0.05;
		SILVER = 0.02;
	}
}

const ALL_CONSTANTS = 3.14 // Not Error
const ALL_CONSTANTS.DISCOUNT.PLATINUM = 0.4 // Not Error
```

예) 상수 고정하기_불변 상수 사용하기

```javascript
export const ALL_CONSTANTS = Object.freeze({
	DISCOUNT : Object.freeze({
		PLATINUM = 0.1;
		GOLD = 0.05;
		SILVER = 0.02;
	})
})

const ALL_CONSTANTS = 3.14 // Error
const ALL_CONSTANTS.DISCOUNT.PLATINUM = 0.4 // Error
```

### 부작용 제거하기

문제 : 부작용이 실행되는 함수가 있다.

→ 부작용 피하기

예) 전역변수 counter 수정

```javascript
let counter = 0;

function incrementCounter(value:number) : void {
	counter += value;
}
```

예) 모든 부작용 피함

```javascript
let counter = 0;

function incrementCounter(counter:number, value:number) : void {
	return counter + value;
}
```

→ 모든 부작용을 피함으로써 기능의 재진입과 이에 대한 예측이 가능해진다.

### 호이스팅 방지하기

문제 : 변수를 선언하기도 전에 사용한다.

→ 변수를 선언하고 범위를 확인한다.

결론 : let, const로 사용

호이스팅 : 렉시컬 환경에서 environmentRecord에 의한 현상, 인터프리터가 코드를 실행하기 전에 변수,함수, 클래스, import가 해당 범위의 맨 위로 끌어올리는 것 처럼 보이는 현상
