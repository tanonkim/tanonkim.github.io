## 5. 클로저

### section1 클로저의 의미 및 원리 이해

클로저는 함수형 프로그래밍 언어에서 등장하는 보편적인 특성이다. (JS의 고유한 개념이 아님)

`Closure` : 함수와 그 함수가 선언될 당시의 lexical environment의 상호관계에 따른 현상

**어떤 함수 A에서 선언한 변수 a를 참조하는 내부함수 B를 외부로 전달할 경우** 

**A의 실행 컨텍스트가 종료된 이후에도 변수 a가 사라지지 않는 현상**

Lexical Environment : outerEnvironReference(실행 컨텍스트의 구성 요소 중 하나)

스코프 : LexicalEnvironment의 environmentRecord, `outerEnvironmentReference`에 의해 유효범위인 스코프가 결정

이 때 스코프 체인이 가능해짐.

A에서 실행한 내부함수 B의 실행 컨텍스트가 활성화된 시점에는 B의 outerEnvironmentReference가 참조하는 대상의 A의 LexicalEnvironment에도 접근이 가능해짐.

`combination`

내부함수에서 외부변수를 참조하는 경우에서 combination 발생

즉, 선언될 당시의 LexicalEnvironment와의 상호관계가 의미가 있을 것.

---

예시1) 외부 함수의 변수를 참조하는 내부 함수

```jsx
var outer = function () {
    var a = 1;
    var inner = function () {
        console.log(a++);
    };
    inner();
};

outer();
```

1. inner 함수 내부에서는  a를 선언하지 않음, 값을 못찾으므로 **outerEnvironmentReference**에 지정된 상위컨텍스트인 **outer의 LexicalEnvironment**에 접근해서 a를 찾음.
2. outer 함수의 실행 컨텍스트가 종료되면 LexicalEnvironment에 저장된 식별자들(a, inner)에 대한 참조를 지움
3. 각 주소에 저장돼있던 값은 참조하는 변수가 하나도 없으므로 GC의 수집 대상이 됨

---

예시2) 외부 함수의 변수를 참조하는 내부 함수2

```jsx
var outer = function () {
    var a = 1;
    var inner = function () {
        return ++a; // inner 함수 내부에서 외부변수 a를 사용함
    }
    return inner(); // 값만 사용하기에 a는 GC에 의해서 버려짐
}

var outer2 = outer();
console.log(outer2);
```

return inner()에서는 inner함수를 실행한 결과를 리턴 

→ outer함수의 실행 컨텍스트가 종료되었다면 a변수를 참조하는 대상이 없어짐

a, inner변수는 종료된 이후 GC에 의해서 소멸됨

**예시1와 예시2의 공통점**

outer의 실행 컨텍스트가 종료된 이후에는 inner 함수를 호출할 수 없음

호출할 수 있는 방법은?

---

예시3) 외부 함수의 변수를 참조하는 내부 함수3

```jsx
var outer = function () {
    var a = 1;
    var inner = function () {
        return ++a;
    }
    return inner; // return inner(); -> return inner()
							    // inner함수의 실행결과 -> **inner함수 자체를 반환 (a가 유지됨)**
}

var outer2 = outer();
console.log(outer2()); // console.log(outer2) -> console.log(outer2())
console.log(outer2());
```

return inner() : 함수의 실행 결과를 반환

return inner   : 함수 자체를 반환

- 예시3의 동작원리
    
    inner함수의 실행컨텍스트의 environmentRecord에는 수집할 정보가 없음.
    
    outerEnvironmentReference에는 **inner함수가 선언된 위치의 LexicalEnvironment**가 참조복사 됨
    
    inner함수는 outer함수 내부에서 선언 → outer함수의 LexicalEnvironment가 담길 것
    

- 예시 3의 의문점
    
    inner 함수의 실행 시점에는 outer함수는 이미 종료가 됨, 어떻게 outer함수의 LexicalEnvironment에 접근?
    
    ⇒ `가비지 컬렉터`의 동작 방식 때문
    
    GC는 어떤 값을 참조하는 변수가 하나라도 있다면 그 값은 수집대상 X
    
    따라서 outer함수의 실행이 종료되더라도 내부 함수 inner은 언젠가 outer2를 실행하므로써 호출될 가능성이 열림
    
    inner함수의 실행 컨텍스트가 활성화되면 outerEnvironment의 outer 함수의 LexicalEnvironment를 필요로 함

### section2 클로저와 메모리 관리

클로저 : 객체지향과 함수형 모두를 아우르는 개념

클로저의 본질적인 특성 : 메모리 누수

관리방법 : 그 필요성이 사라진 시점에는 더는 메모리 소모를 하지 않게 하면 됨

참조 카운트를 0으로 만들면 언젠가 GC가 수거해감

- 참조 카운트를 0으로 만드는 방법
    - 식별자에 참조형이 아닌 기본형 데이터(null, undefined)를 할당
    
    ```jsx
    // return에 의한 클로저의 메모리 해제
    var outer = (function () {
        var a = 1;
        var inner = function () {
            return ++a;
        };
        return inner;
    })();
    console.log(outer);
    console.log(outer);
    **outer = null; // outer 식별자의 inner함수 참조를 끊음**
    console.log(outer);
    ```
    
    ```jsx
    
    // setInterval에 의한 클로저의 메모리 해제
    (function () {
        var a = 0;
        var intervalId = null;
        var inner = function () {
            if (++a >= 10) {
                clearInterval(intervalId);
                **inner = null;**
            }
            console.log(a);
        };
        intervalId = setInterval(inner, 1000);
    })();
    ```
    
    ```jsx
    
    // eventListener에 의한 클로저의 메모리 해제
    (function () {
        var count = 0;
        var button = document.createElement('button');
        button.innerText = 'click';
    
        var clickHandler = function () {
            console.log(++count, 'time clicked');
            if (count >= 10) {
                button.removeEventListener('click', clickHandler);
                **clickHandler = null; // clickaHandler 식별자의 참조를 끊음**
            }
        };
        button.addEventListener('click', clickHandler);
        document.body.appendChild(button);
    })();
    
    ```
    

### section3 클로저 활용 사례

### 3.1 콜백 함수 내부에서 외부 데이터를 사용하고자 할 때

예1)

```jsx
var fruits = ['apple', 'banana', 'peach'];
var $ul = document.createElement('ul'); // 공통 코드

fruits.forEach(function (fruit) { // (A)
    var $li = document.createElement('li');
    $li.innterText = fruit;
    $li.addEventListener('click', function () {     // (B)
        alert('your choice is' + fruit);
    });
    $ul.appendChild($li);
});

document.body.appedChild($ul);
```

(A)에서는 내부에서 외부 변수를 사용하지 않아서 클로저가 없음

(B)에서는 A의 실행종료 여부와 무관하게, B가 실행될 때 outerEnvironmentReference가 A의 LexicalEnvironment를 참조함.

⇒ A가 종료되어도 GC대상에서 제외되어 B가 계속 참조 가능해짐

예2) B를 외부로 분리

```jsx
var fruits = ['apple', 'banana', 'peach'];
var $ul = document.createElement('ul'); // 공통 코드

var alertFruit = function (fruit) {
    alert('your choice is' + fruit);
};

// (A)
fruits.forEach(function (fruit) {
    var $li = document.createElement('li');
    $li.innterText = fruit;
    // (B)
    $li.**addEventListener**('click', alertFruit);
    $ul.appendChild($li);
});

document.body.appedChild($ul);
alertFruit(fruits[1]);
```

⇒ 이렇게 되면 li를 클릭하면 li의 대상이 과일이름이 아니라, [object MouseEvent]가 되어버림

제어권을 addEventListener가 가진 상태, 

예3) bind

```jsx
var fruits = ['apple', 'banana', 'peach'];
var $ul = document.createElement('ul'); // 공통 코드

var alertFruit = function (fruit) {
    alert('your choice is' + fruit);
};

// (A)
fruits.forEach(function (fruit) {
    var $li = document.createElement('li');
    $li.innterText = fruit;
    // (B)
    $li.addEventListener('click', alertFruit.bind(null, fruit));
    $ul.appendChild($li);
});

document.body.appedChild($ul);
alertFruit(fruits[1]);
```

bind로 묶으면 이벤트 객체가 인자로 넘어오는 순서가 바뀜,

함수 내부에서의 this가 원래의 그것과 달라짐

예4) 콜백함수와 클로저 4

```jsx
var fruits = ['apple', 'banana', 'peach'];
var $ul = document.createElement('ul'); // 공통 코드
```

### 5.2 접근권한 제어(정보은닉)

정보은닉 : 어떤 모듈의 내부 로직에 대해 외부로의 노출을 최소화해서 모듈간 결합도를 낮추고 유연성을 높이고자 하는 개념

정보은닉의 종류 : public, private, protected

- JS에는 변수자체에 접근권한을 직접 부여하도록 설계X
- 클로져를 활용하면 함수차원에서 public값, private값을 구분하는 것이 가능함

예1)

```jsx
var outer = function () {
    var a = 1;
    var inner = function () {
        return ++a;
    };
    return inner;
};

var outer2 = outer();
console.log(outer2());
console.log(outer2());
```

outer함수를 종료할 때 inner함수를 반환 → outer함수의 a값을 외부에서도 읽을 수 있음

외부에서는 outer함수가 return한 정보에만 접근 가능 : 

일부 변수에 대한 접근 권한을 부여함

return값이 외부에 정보를 제공하는 유일한 수단

예2) 간단한 자동차 객체 :  객체의 값을 접근해서 원하는 값으로 변경가능

```jsx
var car = {
    fuel: Math.ceil(Math.random() * 10 + 10),
    power: Math.ceil(Math.random() * 10 + 10),
    moved: 0,
    run: function () {
        var km = Math.ceil(Math.random() * 6);
        var wasteFuel = km / this.power;
        if (this.fuel < wasteFuel) {
            console.log('cannot move');
            return;
        }
        this.fuel -= wasteFuel;
        this.moved += km;
    },
};

car.fuel = 100000000; // 객체 값을 변경함
car.power = 100000000;
car.moved = 100000000;
```

예3) 간단한 자동차 객체의 위험을 제거 : 클로저를 활용해서 방어

- 필요한 값만을 return하면 됨

```jsx
var createCar = function () {
    var fuel = Math.ceil(Math.random() * 10 + 10);
    var power = Math.ceil(Math.random() * 10 + 10);
    var moved = 0;

    return {
        get moved() {
            **return moved;**
        },
        run: function () {
            var km = Math.ceil(Math.random() * 6);
            var wasteFuel = km / power;
            if (fuel < wasteFuel) {
                console.log('cannot move');
                return;
            }
            fuel -= wasteFuel;
            moved += km;
            console.log(km + `이동, 총 ${moved} km, left fuel is ${fuel}`);
        },
    };
};

var car = createCar();
car.run(); // 2이동, 총 2 km, left fuel is 19.866666666666667
car.run(); // 1이동, 총 3 km, left fuel is 19.8
car.run(); // 5이동, 총 8 km, left fuel is 19.46666666666667
```

1. 함수에서 지역변수 및 내부함수 생성
2. 외부에서 접근권한을 주고자 하는 대상으로 구성된 참조형 데이터를 return
    
    return한 변수들은 공개 멤버, 나머지는 비공개 멤버가 됨
    

### 5.3 부분적용 함수

부분적용함수 : n개의 인자를 받는 함수에 미리 m개의 인자만 넘겨 기억, 나중에 (n-m)개의 인자를 넘기면 비로소 원래 함수의 실행 결과를 얻는 함수

**예1) bind**

```jsx
var add = function () {
    var result = 0;
    for (let i = 0; i < arguments.length; i++) {
        result += arguments[i];
    }
    return result;
};

var addPartial = add.bind(null, 1, 2, 3, 4, 5);
console.log(addPartial(6, 7, 8, 9, 10)); // 55
```

**예2) 디바운스** 

```jsx
var debounce = function (eventName, func, wait) {
    var timeoutId = null;
    return function (event) {
        var self = this;
        console.log(eventName, 'event 발생');
        clearTimeout(timeoutId);
        timeoutId = setTimeout(func.bind(self, event), wait);
    };
};

var moveHandler = function (e) {
    console.log('move event 처리');
};

var wheelHandler = function (e) {
    console.log('wheel event 처리');
};

document.body.addEventListener('mousemove', debounce('move', moveHandler, 500));
document.body.addEventListener('mousewheel', debounce('wheel', wheelHandler, 700));

```

### 5.4 커링 함수

여러개의 인자를 받는 함수를 하나의 인자로 받는 함수를 하나의 인자만 받는 함수로 나눠서 순차적으로 호출될 수 있게 체인 형태로 구성한 것

```jsx
var curry3 = function (func) {
	return function(a) {
		return function(b) {
			return func(a,b)
		}
	}
}

var getMaxWith10 = curry3(Math.max)(10);
console.log(getMaxWith10(8));
```

```jsx
var curry3 = func => a => b => func(a, b);

var getMaxWith10 = curry3(Math.max)(10);
console.log(getMaxWith10(8));
```

각 단계에서 받은 인자들을 모두 마지막 단계에서 참조할 것이므로 GC되지 않고 메모리에 차곡차곡 쌓였다가, 마지막 호출로 실행컨텍스트가 종료된 후에 한꺼번에 GC의 수거 대상이 된다.

당장 필요한 정보만 받아서 전달, 또 필요한 데이터 받고 전달 → 지연 실행
