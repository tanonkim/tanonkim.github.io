### 스레드

JavaScript는 싱글스레드 언어이다. `싱글스레드`라 한 번에 하나의 작업 수행이 가능하다. 반면 Java, Python는 멀티 스레드를 지원하여 코드 로직을 동시에 수행하는 멀티 작업이 가능하다.

웹 어플리케이션은 네트워크 요청이나 이벤트 처리, 타이머와 같은 작업을 멀티로 처리해야 하는 경우가 많다. 싱글 스레드로 브라우저 동작이 한번에 하나씩 수행하게 되면, 예를 들어 파일을 다운 시 다 다운받기 전까지는 아무것도 못하고 대기해야 한다. 

따라서 파일 다운, 네트워크 요청, 타이머, 애니메이션 등 오래 걸리고 반복적인 작업들은 자바스크립트 엔진이 아닌 브라우저 내부의 `멀티 스레드`인 **Web APIs**에서 비동기 + 논블로킹으로 처리된다.

비동기 + 논블로킹은 메인 스레드가 작업을 다른 곳에 요청하여 대신 실행하고, 그 작업이 완료되면 이벤트나 콜백 함수를 받아 결과를 실행하는 방식이다.

**자바스크립트는 왜 싱글 스레드인가?**

자바스크립트는 1995년에 웹브라우저에서 동적인 웹을 만들기 위해 개발된 스크립트 언어이다. 당시 멀티코어 프로세서가 보편화되지 않았고, 웹브라우저에서 간단한 스크립트 동작을 수행하는데 복잡한 병렬 처리가 필요없어서 메모리 사용량이 적고, 동기화 문제를 피할 수 있는 싱글 스레드로 구현하였다. 

싱글스레드는 오래 걸리는 작업이 실행되면 다른 작업들이 대기해야 하므로 응답성이 떨어진다. 또한 CPU 코어를 여러개 사용할 수 없어 성능이 제한된다. 

이런 문제를 해결하기 위해 언어 자체의 설계를 바꾸는 것 보다는 브라우저의 멀티스레드를 이용하는 자바스크립트의 비동기 프로그래밍을 지원하게 되었다. 이 비동기 프로그래밍의 핵심이 이벤트 루프이다.

\*Web worker 최신기술을 통해 JS도 멀티스레드 구현이 가능해졌다.

### 이벤트 루프

이벤트 루프는 **브라우저의 동작 타이밍**을 제어하는 관리자이다. 

싱글 스레드인 자바스크립트의 작업을 멀티 스레드로 돌려 작업을 동시에 처리시키게 하던가, 여러 작업 중 어떤 작업을 우선으로 동작시킬지 결정하는 컨트롤을 위해 존재한다.

그리고 이벤트 루프는 내부의 CallStack, Callback Queue, WebAPIs 등의 요소를 모니터링하면서 비동기적으로 실행되는 작업들을 관리하고, 이를 순서대로 처리하여 프로그래밍의 실행흐름을 제어한다.

- 이벤트 루프의 동작과정
  1. 자바스크립트의 `setTimeout`이나 `fetch` 와 같은 비동기 자바스크립트로 코드를 브라우저 Web APIs에게 맡기고, 
  2. 백그라운드 작업이 끝난 결과를 콜백 함수 형태로 큐(Callback Queue)에 넣고,
  3. 처리 준비가 되면 CallStack(호출 스택)에 넣어 마무리 작업을 진행한다.

![](/assets/img/2025-03-21/js-event-loop-1-1.png)

이런 이벤트 루프를 이용한 프로그래밍 방식을 이벤트 기반(Event Driven) 프로그래밍이라고 한다. 

**이벤트 기반 프로그래밍**

이벤트기반 프로그래밍은 프로그래밍의 흐름이 이벤트에 의해 결정되는 방식이다. 예를 들어 클릭, 키보드 입력과 같은 이벤트가 발생하면 그에 맞는 콜백함수가 실행된다. 

예) addEventListener(eventName, callBack)

이벤트 기반 프로그래밍으로 비동기 작업을 쉽게 처리할 수 있고, 멀티 스레드 언어에 비해 단순하고 직관적인 코드 작성이 가능하다. 브라우저와 같은 환경에서도 안정적으로 실행을 가능하게 하여 사용자와 상호작용을 높일 수 있다.

### 자바스크립트 엔진 구동환경

자바스크립트를 실행하는 소프트웨어는 웹브라우저와 런타임인 Node.js가 있다. 

### 1. 브라우저의 내부 구성도

브라우저는 웹사이트를 화면에 보여주기 위해 여러가지 역할을 하는 부품으로 이루어져있다. 자바스크립트 비동기 동작의 구성요소로는 Web APIs, Event Table, Callback Queue, Event Loop등이 있다.

![](/assets/img/2025-03-21/js-event-loop-1-2.png)

Call Stack : 자바스크립트 엔진이 코드 실행을 위해 사용하는 메모리 구조

Heap : 동적으로 생성된 자바스크립트 객체가 저장되는 공간

Web APIs : 브라우저에서 제공되는 API 모음, 비동기적으로 실행되는 작업들을 전담하여 처리한다. (DOM, fetch, AJAX, timer함수 등), **멀티쓰레드**

Callback Queue : 비동기 작업이 완료되면 실행되는 함수들이 대기하는 공간

Event Loop : 비동기 함수들을 적절한 시점에 실행시키는 관리자

Event Table : 특정 이벤트(timeout, click, mouse 등)가 발생했을 때 어떤 callback함수가 호출되야 하는지를 알고있는 자료구조 

Stack/Heap/Static Area

### 1.1 Web APIs

Web APIs는 타이머, 네트워크 요청, 파일 입출력, 이벤트 처리 등 브라우저에서 제공하는 다양한 API를 포괄하는 총칭이다. Web API는 브라우저(예) Chrome)에서 멀티 스레드로 구현되어있다. 

그래서 브라우저는 비동기 작업에 대해 메인 스레드를 차단하지 않고 다른 스레드를 사용하여 동시에 처리가 가능하다.

각 API마다 스레드들이 할당되어있고, 이들이 모여 멀티 스레드로 이루어져있다.

**예시**

`setTimeout` 비동기 작업은 Web APIs의 한 종류인 Timer API에서 타이머 스레드를 사용하여 타이머를 실행한다.

`XMLHttps`, `fetch`와 같은 네트워크 API는 네트워크 스레드를 사용하여 네트워크 요청과 응답을 처리한다.

![](/assets/img/2025-03-21/js-event-loop-1-3.png)

- Web APIs의 대표적인 종류는 아래와 같다
  - DOM : HTML 문저의 구조와 내용을 표현하고 조작할 수 있는 객체 (동기)
  - XMLHttpRequest : 서버와 비동기적으로 데이터를 교환할 수 있는 객체, AJAX기술의 핵심 (비동기)
  - Timer API : 일정한 시간 간격으로 함수를 실행하거나 지연시키는 메소드들을 제공 (비동기)
  - Console API : 개발자 도구에서 콘솔 기능 제공
  - Canvas API : `<canvas>`요소를 통해 그래픽/애니메이션을 만들 수 있는 메소드 제공 (동기)
  - Geolocation API : 웹브라우저에서 사용자의 현재 위치 정보를 얻을 수 있는 메소드들을 제공

  \*Web API는 비동기/동기로 처리된다. (모든 처리가 비동기X)

### 1.2 Callback Queue

Web APIs가 여러 API를 묶어 말하듯, Callback Queue도 여러 종류의 Queue를 묶어 총칭하는 개념이다.

Callback Queue에는 Macrotask Queue와 Microtask Queue 두 종류가 있다.

![](/assets/img/2025-03-21/js-event-loop-1-4.png)

MacroTask Queue : setTimeout, setInterval, fetch, addEventListner등 비동기로 처리되는 함수들의 콜백 함수가 들어가는 큐 

MicroTask Queue : promise.then, process.nextTick, MutaitonObserver와 같이 **우선적으로** 비동기로 처리되는 함수들의 콜백함수가 들어가는 큐

Callback Queue의 종류에 따라 이벤트 루프가 콜스택으로 옮기는 순서가 달라진다. 일반적으로 Microtask Queue가 가장 우선순위가 높다. 그래서 Microtask Queue를 먼저 처리하여 비우고, 그 다음 Macrotask Queue의 콜백을 처리한다.

### 2. Node.js 내부 구성도

Node.js 환경에서도 브라우저와 거의 비슷한 구조를 볼 수 있다. 차이점이 있다면 내장된 libuv 라이브러리를 사용하여 비동기 IO를 지원한다. 또 브라우저에서는 Web API를 사용하여 DOM 조작, AJAX 호출, 타이머, 애니메이션 등과 같은 작업을 처리하지만, Node.js에서는 **Web API가 아닌 Node.js API**를 사용하여 파일 시스템 엑세스, 네트워크 엑세스, 암호화, 압축 및 해제 등과 같은 작업을 처리한다. 

예를 들어 Node.js에서 HTTP 요청을 하면 http 모듈을 사용한다. 일부 Web API를 사용하기도 하는데, setTimeout, setInterval이 예시이다.

![](/assets/img/2025-03-21/js-event-loop-1-5.png)

Node.js에서 자바스크립트 엔진은 비동기 작업을 위해 Node.js의 API를 호출하며, 이 때 넘겨진 콜백은 libuv의 이벤트 루프를 통해 스케쥴되고 실행된다.

내부 구성으로는 아래와 같다.

V8(js 엔진) : Node.js에서 사용하는 Javascript 엔진으로 코드를 컴파일하고 실행한다.

Bindings : Node.js 시스템과 V8 엔진간의 상호작용을 가능하게 하는 C++ 라이브러리

libuv 라이브러리 : Node.js에서 비동기 I/O 작업을 처리하기 위한 C 라이브러리

Event Queue : 비동기 I/O 작업 결과를 저장하고 처리하기 위한 자료구조

Event Loop : Event Queue에 저장된 I/O 작업 결과를 처리하고, 다음 작업을 수행하도록 하는 관리자

Wocker Threads : CPU 집약적인 작업을 처리하기 위해 Node.js 10부터 추가된 멀티 쓰레드. 메인 쓰레드와 독립적인 V8 인스턴스를 가진다.
