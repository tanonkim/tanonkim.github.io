### 객체지향 개념, 특징

객체지향 프로그래밍이란 많은 객체들이 모여서 상호 협력하면서 데이터를 처리하는 프로그래밍 설계방식이다. ⇒ 요약 : 프로그램을 묶음 단위로 잘게 쪼개서 추후에 가져다 쓰기 편하게 만들어놓은 프로그램이 방식이다.

컴포넌트가 유연하고 변경이 쉽다는 장점 때문에 현업에서 대규모 소프트웨어 개발에 많이 사용된다. Java, Python, C++, Kotlin 등이 모두 객체지향 요소를 가진 언어이다.

객체지향 프로그래밍의 반대 개념으로는 **절차적 프로그래밍**이다. function(함수)를 이용해서 정리정돈하는 프로그래밍 기법이다. ⇒ 함수를 이용해서 작은 부품을 만들고, 이것을 결합해서 더 큰 프로그램을 만들어가는 테크닉이다.

기술이 발전되고, 더 복잡한 어플리케이션에 대한 수요가 증가하면서 절차적 프로그래밍의 한계가 나타났다. 복잡한 어플리케이션을 위해서는 실제 세계처럼 더 밀접한 모델링 방식이 필요했기 때문이다.

그래서 함수(Method)와 변수(Variable)을 모아서 Class라는 박스를 만들고 정리정돈 가능한 수납상자를 만들었다. 이런 Class 중심으로 프로그램의 구조를 만들어가는 프로그래밍 방법론이 OOP(객체지향 프로그래밍)이다.

### 추상화

컴퓨터 과학에서 추상화는 복잡한 자료/모듈/시스템 등 핵심적인 개념, 기능을 간추려 내는 것을 말한다.

보통 알고는 있지만 정확하게 표현하기 힘든 것들을 중요한 부분이나 특징점을 잡아 설명하는 것을 추상적으로 표현한다고 말할 수 있다.

객체지향 프로그래밍에서도 이 추상화는 중요한 개념 중 하나이다.

프로그래밍에서의 추상화는 클래스를 정의할 때 불필요한 부분들을 생략하고 객체의 속성 중 중요한 것에만 중점을 두어 개략화하는 것을 말한다.

→ 클래스의 중요하고 공통된 성질들을 추출하여 부모(슈퍼 클래스) 클래스를 선정하고, 이벤트 발생의 정확한 절차나 방법을 정의하지 않고 대표할 수 있는 표현으로 대체하는 것을 말한다.

### 제어 추상화

제어 추상화는 어떤 클래스의 메소드를 사용하는 사용자에게 해당 메소드의 작동방식과 같은 내부 로직을 숨기는 것을 말한다. → 내부 동작(알고리즘, 절차 등)을 감추고 단순한 인터페이스만 노출

예) start(), stop()만 있는 API → 사용자는 내부 로직을 몰라도 된다.

### 데이터 추상화

데이터 추상화란 대상을 간단한 개념으로 일반화하는 과정을 말한다.

서로 다른 구현 객체들의 공통 속성/행동을 상위 개념으로 묶음 (클래스, 인터페이스)

⇒ 추상화를 하면 할 수록 객체의 디테일함은 사라지고 공통된 특징만 남게 된다.

예) 갤럭시 > 휴대폰 > 통신기기 > 전자제품

그리고 추상화한 상위 요소부터 각 요소에 맞는 기능들을 정의한다.

갤럭시(갤럭시 AI) > 휴대폰(카메라, 게임) > 통신기기(통화) > 전자제품 (전원)

갤럭시 제품 하나만 만들 때에는 비효율적으로 보일 수 있지만, 제품 종류가 늘어날 수록 장점으로 작용된다. 왜나하면 공통 기능을 미리 개발해두면 기능 상속을 통해 빠르게 구조를 확장할 수 있기 때문이다.

→ 설계의 관점 : 무엇을 노출할까

### 키워드

인터페이스/contract : 외부에 노출되는 사용법 (함수 시그니처, props, 타입)

구현 은닉 : 내부 로직은 변경가능, 인터페이스는 유지하기

캡슐화 : 상태, 행위의 묶음과 접근 통제

SoC(관심사의 분리) : UI/로직/데이터 층 분리

레벨별 추상화 - low level : 구현 ↔ high level : 도메인

합성 VS 상속 : 합성 사용하기 : 유연성

재사용성, 테스트성, 유지보수성 : 추상화의 기대효과

과도한 추상화의 위험 : 불필요한 복잡성, 이해 난이도 증가
