선언적 코드 : 성취하기 위해 해야 할 단계를 명시하는 것이 아니라, 프로그램이 무엇을 해야 하는지 설명하는 프로그래밍 코드의 한 종류

→ 결과를 성취하는 과정/방법 보다는 원하는 결과/무엇에 초점을 둔다.

선언적 코드는 주로 함수형 프로그래밍을 지원하는 프로그래밍 언어에서 활용된다.

### 재사용 변수 범위 좁히기

문제 : 동일한 변수를 다른 변수 범위에서 재사용하고 있다.

→ 동일한 변수를 다른 용도로 쓰거나 읽지 않고, 모든 지역 변수의 최소 범위를 정의하기

예) total 변수의 재사용

```java
double total = item.getPrice() * item.getQuantity();
System.out.println("total is : " + total);


total = order.getTotal() - order.getDiscount();
System.out.println("total cost is : " + total);
```

예) 변수의 범위를 좁혀 두 개의 블록으로 나누기

```java
function printLineTotal() {
	double lineTotal = item.getPrice() + item.getQuantity();
	System.out.println("total is : " + lineTotal);
}

function printAmountTotal() {
	double amountTotal = order.getTotal() - order.getDiscount();
	System.out.println("total is : " + amountTotal);
}
```

### 빈 줄 제거하기

문제 : 빈 줄로 구분된 큰 코드 블록이 존재

→ 메서드를 객체로 추출해 동작을 구분하는 블록을 구분하기

예) 메서드로 분리되지 않은 코드 블록

```php
function translateFile() {
    $this->buildFilename();
    $this->readFile();
    $this->assertFileContentsAreOk();
    // 더 많은 줄이 있음
    
    // 기존 묶음의 끝을 표현하기 위해 빈 줄 기입
    $this->translateHiperLinks();
    $this->translateMetadata();
    $this->translatePlainText();
    
    // 이전과 똑같은 상황으로 빈 줄 기입
    $this->generateStats();
    $this->saveFileContents();
    // 더 많은 줄이 있음
}
```

예) 메서드를 객체로 추출한 코드 블록

```php
function translateFile() {
    $this->readFileToMemory();
    $this->translateContents();
    $this->generateStatsAndSaveFileContents();  
}
```

함수가 짧을 수록 가독성이 좋아지고, KISS원칙을 따른다. 그리고 재사용 가능성이 증가된다.

### 이중 부정 제거하기

문제 : 부정적인 조건의 이름을 가진 메서드가 존재

### 잘못 배치된 책임 변경하기

문제 : 메서드가 객체에 부적절하게 배치되어있다.

→ MAPPER개념을 이용해 올바른 위치를 찾을 수 있도록 적절한 객체를 생성하거나 오버로드 해야 한다.

예) add의 책임에 대한 예제

```javascript
Number>>#add: a to:b
```

많은 프로그래밍 언어에서 자연스럽지만, 실생활에서는 부자연스럽다.

예) PI상수를 정의하는 다른 예제

```javascript
class GraphicEditor {
	constructor() { // 상수를 여기에 정의하면 안된다.
		this.PI = 3.14; 
	}
	
	pi() { // 이는 객체의 책임이 아니다.
		return this.PI;
	}
	
	drawCircle(radius) {
		console.log(`둘레 is ${(2 * this.pi()) * radius}`)
	}
}
```

예) RealConstants객체로 책임 옮기기

```javascript
class GraphicEditor {
	drawCircle(radius) {
		console.log(`둘레 is ${2 * RealConstants.pi() * radius}`)
	}		
}

class RealConstants {
	pi() {
		return 3.14
	}
}
```

### 명시적 반복 대체하기

문제 : 열거자와 반복자는 차세대 코드이며, 더 높은 수준의 추상화가 필요하다.

→ 반복하는 동안 인덱스 사용하지 않기. 고수준의 컬렉션 이용하기

인덱스는 종종 캡슐화를 깨고, 코드를 덜 선언적으로 만들기 때문에 주의가 필요하다. 고차함수를 지원한다면 foreach()나 고차 반복자를 선호하고, 구현 세부사항을 숨긴다면 yield(), 캐시, 프록시, 지연로딩 등 더 많이 사용할 수 있다.

예) for i

```javascript
for (let i = 0; i < colors.length; i++) {
	console.log(colors[i]);
}
```

예) 더 선언적이고, 고수준으로 표현된 예제

```javascript
colors.forEach((color) => {
		console.log(color);
})
```

### 설계 결정 기록하기

문제 : 코드에 중대한 결정을 내릴 때 그 이유를 문서화하고 싶다.

→ 선언적이고, 의도를 드러내는 이름 사용하기

예) 명시적이지 않은 설계 결정 예

```javascript
set_memory("512K");
run_process();
```

예) 메모리 증가 이유에 대한 힌트를 제공하는 명시적인 예제

```javascript
increase_memory_to_avoid_false_positives();
run_process();
```

### 매직 넘버를 상수로 변경하기

문제 : 많은 숫자를 사용하는 메서드가 존재하나, 해당 숫자에 대한 의미와 설명이 불분명

→ 설명이 없는 매직 넘버 피하기

예) 매직넘버

```javascript
function energy(mass) {
	return mass * (299792 ** 2);
}
```

예) 상수로 변경

```javascript
function energy(mass) {
	return mass * (LIGHT_SPEED_KILOMETERS_OVER_SECONDS ** 2);
}
```

### 콜백 지옥에서 벗어나기

문제 : 과도하게 중첩되어 읽기 및 유지하기 어려운 콜백을 사용하는 비동기 코드가 있다.

→ 콜백을 사용하지 말고 시퀀스 작성하기

예) 콜백 지옥

```javascript
asyncFunc1(function (error, result1) {
  if (error) {
    console.log(error);
  } else {
    asyncFunc2(function (error, result2) {
      if (error) {
        console.log(error);
      } else {
        asyncFunc3(function (error, result3) {
          if (error) {
            console.log(error);
          } else {
            // 중첩 콜백은 계속 이루어집니다...
          }
        });
      }
    });
  }
});
```

예) 기명함수를 사용하기_시퀀스 작성하기

```javascript
function asyncFunc1() {
	return new Promise((resolve, reject) => {
		// 비동기작업
		
		// success
		resolve(result1)
		
		// fail
		reject(error);
		
	}) 
}

function asyncFunc2() {
	return new Promise((resolve, reject) => {
		// 비동기작업
		
		// success
		resolve(result1)
		
		// fail
		reject(error);
		
	}) 
}

async function performAsyncOperations() {
	try {
		const result1 = await asyncFunc1();
		const result2 = await asyncFunc2();
		const result3 = await asyncFunc3();
		
	} catch (error) {
		console.log(error);
	}
}

performAsyncOperations();
```

### 마법 변환 피하기

문제 : 마법같은 문장을 더 명확히 만들고, 빠르게 실패하기 원칙을 준수하게끔 하기

→ 마법같이 변환되는 코드 제거

예) 마법변환

```javascript
new Date(31, 02, 2020);

1 + 'Hello'; // 대부분 언어에서 실행됨

!3;
```

예)

```javascript
new Date(31, 02, 2020);
// Throw Error

1 + 'Hello';
// Type Error

!3;
// boolean
```

`+` 메서드를 실행하면 모델과 실제 세계의 결과가 다르다.
