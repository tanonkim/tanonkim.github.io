### 소개

데이터가 중요한 시대에 살고 있다. → 데이터 관리 및 보호하고 동작을 노출하는 동시에 정보와 우발적인 표현을 숨겨 결합을 피할 수 있는 시뮬레이터를 만들어야 한다.

### 작은 객체 생성하기

문제 : 기본형 타입만 필드로 포함하는 큰 객체가 존재한다.

→ 작은 객체에 대한 책임을 MAPPER에 찾고 이를 구체화한다.

**JAVA 예시**

예) Person의 이름은 문자열과 다르게 동작한다.

```java
public class Person {
	private final String name;
	
	public Person(String name) {
		this.name = name;
	}
}
```

예) 이름의 개념을 구체화한 예제

```java
public class Name{
	private final String name;
	
	public Name(String name) {
		this.name = name;
	}
}

public class Person {
	private final Name name;
	
	public Person(Name name) {
	  // 이 곳에 유효성 검증을 추가하지 않아도 된다.
		this.name = name;
	}
}
```

예) 단순버전 (문자열 직접 사용)

```typescript
class Person {
  private readonly name: string;

  constructor(name: string) {
    this.name = name;
  }

  getName(): string {
    return this.name;
  }
}
```

---

개선된 버전 (이름을 작은 객체로 구체화)

```typescript
class Name {
  private readonly value: string;

  constructor(value: string) {
    if (value.trim().length === 0) {
      throw new Error("이름은 비어 있을 수 없습니다.");
    }
    if (value.length > 50) {
      throw new Error("이름은 50자 이하이어야 합니다.");
    }
    this.value = value;
  }

  public getValue(): string {
    return this.value;
  }

  public equals(other: Name): boolean {
    return this.value === other.value;
  }
}

class Person {
  private readonly name: Name;

  constructor(name: Name) {
    this.name = name;
  }

  public getName(): Name {
    return this.name;
  }
}

// 사용 예시
const name = new Name("Alice");
const person = new Person(name);

console.log(person.getName().getValue()); // "Alice"

```

### 기본형 데이터 구체화하기

문제 : 기본형 타입이 난무하는 객체가 있다.

→ 기본형 타입 대신 작은 객체들 사용하기

예)

```java
int port = 8080;
InetSocketAddress in = open("example.org", port);
String uri = urifromPort("example.org", port);
String address = addressFromPort("example.org", port);
String path = pathFromPort("example.org", port);
```

해당 코드의 문제

1. 묻지 말고 말하라는 원칙
2. MAPPER 설계 규칙을 따르지 않고 하위 집합 원칙을 위반한다.

⇒ **작은 객체를 만들고** 무엇과 어떻게를 분리하는 작업을 해야 한다.

예) 수정 예시

```java
Port server = Port.parse(this, "www.example.org:8080");

Port in = server.open(this);
URI uri = server.asUri(this);
InetSocketAddress address = server.asInetSocketAddress();
Path path = server.path(this, "/index.html");
```

→ 추상화 발견을 위해 노력해야 한다.

### 연관 배열 재구성하기 → 이해 잘 못함

문제 : 연관 배열을 통해 실제 세상의 객체를 빈약하게 나타내고 있다.

→ 신속한 프로토타이핑에는 배열을 사용하고 중요한 비즈니스에는 객체 사용하기

연관 배열은 빈약한 객체로 표현되기 쉽다

→ 풍성한 객체로 보유하기

1. 풍성한 객체를 보유하면 코드를 깔끔하게 정리하는게 가능하고
2. 무결성을 유지
3. 코드 중복을 피하고 일관성 확보

예) 빈약하고 기본형 집착인 코드

```php
$coordinate = array('latitude'=>1000, 'longitude'=>2000); 
// 수많은 기본 데이터를 가진 배열일 뿐입니다.
```

예) 진단사에 의해 더 정확해짐

```php
final class GeographicCoordinate {

    function __construct($latitudeInDegrees, $longitudeInDegrees) {
        $this->longitude = $longitudeInDegress;
        $this->latitude = $latitudeInDegress;
    }
}

$coordinate = new GeographicCoordinate(1000, 2000);
// 이 값은 지구상에 존재하지 않으므로 오류를 발생시켜야 합니다.
```

예) 처음부터 유효한 객체가 존재해야 한다.

### 문자열 남용 제거하기

문제 : 구문분석, 구문분해, 정규표현식, 문자열 비고, 하위 문자열 검색 및 문자열 조작 함수가 많다.

→ 실제 추상화와 실제 객체로 우발적 문자열 조작을 대체

예) 문자열 조작을 많이 하는 예제

```php
$schoolDescription = 'College of Springfield';

preg_match('/[^ ]*$/', $schoolDescription, $results);
$location = $results[0]; // $location = 'Springfield'.

$school = preg_split('/[\s,]+/', $schoolDescription, 3)[0]; //'College'
```

예) 선언적인 버전으로 변환한 코드

```php
class School {
    private $name;
    private $location;

    function description() {
        return $this->name . ' of ' . $this->location->name;
    }
}
```

⇒ MAPPER에 존재하는 객체를 찾으면 코드가 더 선언적이고, 더 많은 테스트를 수행할 수 있다.

또 새로운 추상화에 제약 조건을 추가하는게 가능하다.

### 하위 집합을 객체로 구체화하기

문제 : 상위 집합 도메인에서 객체를 모델링하고 유효성 검증 중복이 많이 존재한다.

→ 작은 객체들을 생성하고 제한된 도메인에 대해 유효성 검증하기

```java
public class EmailAddress {
    public string emailAddress;

    public EmailAddress(string address) {
        string expressions = @"^\w+([-+.']\w+)*@\w+([-.]\w+)*\.\w+([-.]\w+)*$";
        if (!Regex.IsMatch(address, expressions)) {
            throw new Exception("이메일 주소가 유효하지 않습니다.");
        }
        this.emailAddress = address;
    }
}

destination = new EmailAddress("destination@example.com");
```
