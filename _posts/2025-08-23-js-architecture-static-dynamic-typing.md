## 1. 타입이 왜 중요한가 (정적 타이핑/ 동적 타이핑)

### 데이터 타입이란?

데이터 타입은 값의 종류이다. 자바스크립트에선 다양한 타입을 지원하는데, 원시 타입, 객체 타입으로 나눌 수 있고, 원시 타입은 number, string, boolean, undefined, null, symbol이 포함되고 객체타입은 객체, 배열, 함수 등이 존재한다.

조금 더 컴퓨터 공학의 개념으로 접근하면 데이터 타입은 저장 가능한 메모리 크기라고 정의할 수 있다.

예) C언어

c언어의 int는 정수를 저장하는 타입이 아닌, 4바이트의 데이터를 저장하는 타입이다.

`char var = ‘a’`

유니코드에 따르면 a는 정수 97로 변환된다. 즉 char 데이터에 정수가 들어간 것인데, 에러가 발생되지 않는다. 그래서 데이터 타입은 값의 종류가 아닌, 저장 가능한 메모리 크기이다.

### 메모리를 신경쓰고 코딩하기

컴퓨터의 성능이 크게 발전해서, 당장 메모리에 대해 크게 신경쓰지 않고도 무언가를 빠르게 개발할 수 있다. 하지만, 메모리를 생각하지 않는 것은 지속가능성이 떨어지는 프로그램이다.

타입 선언에 따른 메모리는 몇 바이트지만, 많이 쌓이게 되면 프로그램이 심각하게 무거워질 수 있다.

### `정적 타이핑`

정적 타이핑 언어는 변수의 타입을 `컴파일 타임`에 결정한다. 이는 코드의 안정성을 높이고, 타입 관련 오류를 사전에 방지할 수 있다. 왜냐하면 컴파일러가 타입의 오류를 사전에 발견하기 때문이다.

예) c언어 변수 선언

```c
int var = 10;
float var1 = 3.14;
chat str = 'a';
```

c언어에서 변수를 선언할 때 타입을 써야 한다. 한번 타입이 정해진 식별자는 다른 타입의 값을 넣을 수 없고 선언한 데이터 타입에 적절한 값을 할당한지 검사하고, 통과하지 못하면 에러를 발생시킨다.

### `동적 타이핑`

**동적 타이핑 언어는 `런타임`에 타입 지정이 실행된다.**

JavaScipt와 Python은 데이터 타입을 직접 선언하지 않는다. 변수의 타입은 런타임에 결정되는데, 이를 동적 타이핑이라고 한다.

동적 타이핑 언어는 사용자가 직접 타입을 지정하지 않는다. 사용자는 값을 대입하고 자바스크립트 엔진은 사용자가 대입한 값을 바탕으로 타입을 지정한다. 그래서 동적 타이핑은 코드 작성 시 유연성을 제공하지만, 런타임 에러를 발생시킬 수 있는데 이는 코드의 디버깅을 어렵게 할 수 있고, 코드의 안정성을 저해하는 단점이 있다.

정적 타입과 비교해서 지정하는 방식에서 차이가 있지만, 동적 타이핑 언어들도 결국 타입을 선언해야 한다. 단지 누가 언제 하느냐에 대한 차이가 존재한다. 즉 동적 타이핑은 식별자를 선언할 때가 아닌, 값을 할당할 때 타입이 정해진다.

## 2. 타입스크립트

### 타입스크립트의 도입과 장점

타입스크립트는 자바스크립트의 상위 집합으로 `정적 타이핑`을 지원한다. 자바스크립트의 유연성을 유지하면서도 코드의 안정성을 높일 수 있는 장점이 있다. → 타입스크립트는 변수의 타입을 명시적으로 선언할 수 있어, 코드의 가독성과 유지보수성을 높인다. (컴파일 때 타입 검사를 수행한다.)

- 장점

  타입스크립트는 타입 검사를 통해 코드 오류를 사전에 방지가능하기에, 대규모 프로젝트에서 특히 유용하다. 이는 코드의 품질을 높이고, 개발의 속도를 높인다.

  타입스크립트는 자바스크립트와 호환성이 뛰어나서, 기존 프로젝트에 쉽게 도입할 수 있게 한다. 기존 코드를 크게 수정하지 않고도 타입스크립트를 사용할 수 있게 한다.

  타입스크립트는 다양한 개발도구와의 통합이 용이하다. 개발자가 효율적으로 코드를 작성하고, 디버깅할 수 있게 한다. 다양한 iDE와의통합을 통해 코드 작성 시 실시간으로 타입 검사를 제공한다.

### 타입스크립트와 자바스크립트의 차이점

타입 스크립트는 정적 타이핑을 지원한다는 점이 큰 차이점이다. 타입스크립트는 자바스크립트의 상위 집합으로 자바스크립트의 모든 기능을 지원한다. 호환성을 유지하기에 기존 자바스크립트 코드를 타입스크립트로 쉽게 변환할 수 있게 한다.

타입스크립트는 컴파일 타임에 검사를 수행하기에 코드의 오류를 사전에 방지한다. 이는 코드의 품질을 높이고, 디버깅 시간을 줄이는데 기여한다.
