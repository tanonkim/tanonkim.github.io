## This
this : 함수와 객체의 구분이 느슨한 자바스크립트에서 this는 실질적으로 둘을 구분하는 유일한 기능

### section1 : 상황에 따라 달라지는 this

실행 컨텍스트는 함수를 호출할 때 생성, 즉 this는 함수를 호출할 대 결정

### **1.1 전역 공간에서의 this**

```jsx
console.log(this);
console.log(window);
console.log(this === window) // true
```

**전역 변수와 전역 객체**

```jsx
var a = 1;
console.log(a); // 1
console.log(window.a); // 1
console.log(this.a); // 1, 전역 공간에서 this는 전역 객체를 의미
```

왜 모든 값들이 1인가? : js의 모든 변수는 특정 객체의 프로퍼티로서 동작.

- 특정 객체 : 실행 컨텍스트의 LexicalEnvironment

→ 전역변수를 선언하면 js엔진은 이를 전역객체의 프로퍼티로 할당한다.

### **1.2 메서드로서 호출할 때 그 메서드 내부에서의 this**

- 함수 vs 메서드
    - 함수 : 그 자체로 **독립적인 기능 수행**
    - 메서드 : 자신을 호출한 대상 객체에 관한 동작을 수행

```jsx
var func = function(x) {
	console.log(this, x)
}
func(1) // Window {...} 1 

var obj = {
	method : func
}
obj.method(2); // {method f} 2 
```

익명 함수는 그대로이지만, 변수에 담아 호출한 경우와 obj 객체의 프로퍼티에 담아 호출하는 경우 this가 달라짐

**메서드 내부에서의 this**

함수를 메서드로서 호출하는 경우 : 호출 주체는 함수 명 앞의 객체

점 표기법으로서 호출하는 경우     : 마지막 점 앞의 명시된 객체

```jsx
var obj = {
    methodA: function () {
        console.log(this);
    },
    inner: {
        methodB: function () {
            console.log(this);
        },
    },
};

obj.methodA();
obj['methodA']();           // {  methodA: f,  inner: {...}} // obj랑 같음

obj.inner.methodB();        // { methodB: [Function: methodB] } // obj.inner와 같음
obj.inner['methodB']();     // 메서드로서 호출
obj['inner'].methodB();
obj['inner']['methodB']();

const test = obj.methodA;
test(); // (window or global) 이유 : 함수는 그 자체로 독립적으로 실행

```

### 1.3 함수로서 호출할 때 그 함수 내부에서의 this

```jsx
var obj1 = {
    outer: function () {
        console.log(this); // (1) { outer: f }, obj1랑 같음

        var innerfunc = function () {
            console.log(this); // (2) : window, (3) : obj2
        };

        innerfunc();

        var obj2 = {
            innerMethod: innerfunc,
        };
        obj2.innerMethod();
    },
};

obj1.outer();
```

(1) : obj1.outer의 함수 실행컨텍스트가 생성되면서 호이스팅, 스코프 체인 정보 수집하고 this를 바인딩

obj1.outer로 실행, 즉 outer 앞에 `.`점이 있음 ⇒ 메서드로서 호출됨

(2) : 함수를 실행할 때 앞에 `.`점이 없음 ⇒ 함수로서 호출한 것이므로 this가 지정되지 않음 : window객체가 바인딩됨

(3) : obj2는 객체를 할당, innerMethod라는 프로퍼티를 할당, innerfunc랑 연결

obj2.innerMehtod를 실행하므로, 즉 앞에 **`.`**점이 있으므로 this는 obj2

참고) this의 우회방법 1

```jsx
var obj1 = {
    outer: function () {
        var self = this; // outer의 this랑 같음 === obj1.outer()의 this랑 같다는 얘기!
        var innerfunc2 = function () {
						console.log(self); // 내부함수에서 this를 우회하는 방법
        };
        innerfunc2();
    },
};

obj1.outer();
```

참고) this의 우회방법 2, 화살표 함수

화살표 함수는 this를 바인딩하지 않음

```jsx
var obj = {
    outer: function () {
        console.log(this); // obj1

        var innerFunc = () => {
            console.log(this); // obj1
        };
        innerFunc();
    },
};

obj.outer();

```

### 1.4 콜백 함수 호출 시 그 함수 내부에서의 this

콜백 함수 : A의 제어권을 B(다른 함수/메서드)에게 넘겨주는 경우

```jsx
// 1)
setTimeout(() => {
    console.log(this); // this : global, (함수로써 실행됨_콜백함수도 함수)
}, 300);

// 2)
[1,2,3,4,5].forEach(function (x) {
    console.log(x, this); // this : global, (함수로써 실행됨_콜백함수도 함수)
});

// 3)
document.body.innerHTML += '<button id="a">click</button>'
document.body.querySelector('#a')
    .addEventListener('click', function (e) {
        console.log(this, e) // this : document.body.querySelector('#a')
    })
```

### 1.5 생성자 함수 내부에서의 this

**생성자 함수 : 공통된 성질을 지니는 객체들을 생성하는데 사용하는 함수**

구체적인 인스턴스를 만들기 위한 일종의 틀

new로 호출을 하면 생성자의 prototype 프로퍼티를 참조하는 __proto__라는 객체를 생성, this에 부여

```jsx
var Cat = function (name, age) {
    this.bark = '야옹';
    this.name = name;
    this.age = age;
};

var choco = new Cat('choco', 9); // this : choco의 인스턴스
var navii = new Cat('navii', 2); // this : navii의 인스턴스
console.log(choco, navii); // choco, navii의 인스턴스 객체가 출력
```

this는 choco, navii의 인스턴스를 가리킴

### section2 : 명시적으로 this를 바인딩하는 방법

### 2.1 call 메서드

call 메서드를 이용하면 임의의 객체를 this로 지정 가능

```jsx
var func = function (a, b, c) {
    console.log(this, a, b, c);
};

func(1, 2, 3);                // window
func.call({ x: 1 }, 1, 2, 3); // {x : 1}

```

```jsx
var obj = {
    a: 1,
    method: function (x, y) {
        console.log(this.a, x, y);
    },
};

obj.method(2, 3);                // 1,2,3
obj.method.call({ a: 4 }, 5, 6); // 4,5,6
```

### 2.2 apply 메서드

```jsx
var func = function (a, b, c) {
    console.log(this, a, b, c);
};
func.apply({ x: 1 }, [4, 5, 6]);

var obj = {
    a: 1,
    method: function (x, y) {
        console.log(this.a, x, y);
    },
};

obj.method.apply({ a: 4 }, [5, 6]);

```

### 2.3 call/apply 메서드의 활용

```jsx
function Person(name, gender) {
    this.name = name;
    this.gender = gender;
}

function Student(name, gender, school) {
    Person.call(this, name, gender);
    this.school = school;
}

function Employee(name, gender, company) {
    Person.apply(this, [name, gender]); // 여러 인수를 하나로 묶고 싶을 때
    this.company = company;
}

var tanon = new Student('tanon', 'male', 'Konkuk');
var kihyeon = new Employee('kihyeon', 'femail', 'clip');

```

### 2.4 bind 메서드

call과 비슷하지만 즉시 호출하지는 않고 넘겨 받은 this 및 인수를 바탕으로 새로운 함수를 반환하기만 함

```jsx
var func = function (a, b, c, d) {
    console.log(this, a, b, c, d);
};
func(1, 2, 3, 4);      // window, 1 2 3 4

var bindFunc1 = func.bind({ x: 1 });
bindFunc1(5, 6, 7, 8); // {x:1} 5 6 7 8

var bindFunc2 = func.bind({ x: 1 }, 4, 5);
bindFunc2(6, 7);       // {x:1} 4 5 6 7
bindFunc2(99, 100);    // {x:1} 4 5 99 100
```

상위 컨텍스트의 this를 내부함수/콜백함수에 전달하기

```jsx
var obj1 = {
    outer: function () {
        console.log(this);
        var innerFunc = function () {
            console.log(this);
        };
        innerFunc.call(this);
    },
};
obj1.outer(); // obj1

var obj2 = {
    outer: function () {
        console.log(this);
        var innerFunc = function () {
            console.log(this);
        }.bind(this);
        innerFunc(); // var self = this로 넘겨주는거랑 같음
    },
};
obj2.outer(); // obj1

var obj3 = {
    outer: function () {
        console.log(this);
        const self = this;
        var innerFunc = function () {
            console.log(self);
        };
        innerFunc();
    },
};
obj3.outer(); // obj1

```

### 2.5 화살표 함수의 예외사항

this는 아예 없음, 접근하고자 하면 스코프 체인 상 가장 가까운 this에 접근하게 됨

→ call, apply, bind를 할 필요가 없음
