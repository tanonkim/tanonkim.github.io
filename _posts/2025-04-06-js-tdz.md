> TDZ를 모른 채 자바스크립트 변수를 사용하지 말자

예1) 인스턴스를 생성한 다음 클래스 선언

```javascript
new Car('red');  // Cannot access 'Car' before initialization

class Car {
  constructor(color) {
    this.color = color;
  }
}
```

예2) 함수를 실행한 다음 함수 선언

```javascript
greet('World');

function greet(who) {
	return `Hello, ${who}!`;
}
```

예1)은 `ReferenceError` 가 발생하고, 예2) 코드는 잘 작동한다. TDZ는 `let`, `const`, `class` 구문의 유효성을 관리한다. 자바스크립트에서 변수가 동작하는 방식은 중요하다.

## 1. TDZ

TDZ 시맨틱은 선언 전에 변수에 접근하는 것을 금지한다. 변수 선언 전에는 어떠한 것도 허용하지 않는다.

const 변수를 선언하고 초기화하면 변수에 접근이 가능하다.

```javascript
const white = '#FFFFFF';
white; // '#FFFFFF'
```

그러나 선언 전에 white를 접근하면 `ReferenceError` 에러가 발생한다.

```javascript
white; // throws `ReferenceError`
const white = '#FFFFFF';

white // '#FFFFFF'
```

white변수는 `const white = '#FFFFFF’` 구문 전까지 TDZ에 존재한다. 

TDZ에 있는 white 변수에 접근하면 ReferenceError : Cannot access ‘white’ before initialization 에러가 발생한다.

## 2. TDZ의 영향을 받는 구문

### const 변수

const 변수는 선언한 후에 사용해야 한다.

```javascript
const pi = 3.14;

// Works!
pi; // => 3.14
```

### let 변수

let 변수도 선언 이후에 사용해야 한다.

```javascript
let count;

// Working
count; // undefined
count = 10;

// Working
count; // 10
```

### class 변수

```javascript
const myCar = new Car('red'); // ReferenceError: Cannot access 'Car' before initialization

class Car{
	constructor (color) {
		this.color = color;
	}
}
```

이 코드가 동작하려면 클래스를 선언한 후에 사용하도록 수정한다.

```javascript
class Car{
	constructor (color) {
		this.color = color;
	}
}
const myCar = new Car('red'); 
console.log(myCar.color); // red
```

### constructor() 내부의 super()

예) 오류 예시

```javascript
class Car{
	constructor (color) {
		this.color = color;
	}
}

class MuscleCar extends Car {
	constructor(color, power) {
		this.power = power; 
		super(color); // super로 부모의 생성자가 먼저 호출되어야 함
	}
}

const myCar = new MuscleCar('red', '300'); // ReferenceError: Must call super constructor in derived class before accessing 'this' or returning from derived constructor
console.log(myCar); // Error
```

부모클래스를 상속받았으면 생성자 안에서 `super()`를 호출하기 전까지 this바인딩은 TDZ에 있다. 

TDZ는 인스턴스를 초기화하기 위해 부모 클래스의 생성자를 호출할 것을 제안한다.즉, super()가 먼저 와야 한다. 

부모 클래스의 생성자를 호출하고 인스턴스가 준비되면 자식 클래스에서 this 값을 변경할 수 있다.

예) 수정된 예시

```javascript
class Car{
	constructor (color) {
		this.color = color;
	}
}

class MuscleCar extends Car {
	constructor(color, power) {
		super(color);
		this.power = power; 
	}
}

const myCar = new MuscleCar('red', '300'); 
console.log(myCar);

```

### 기본 함수 매개변수

기본 매개변수는 글로벌과 함수 스코프 사이의 중간 스코프에 위치한다. 기본 매개변수 또한 TDZ 제한이 있다.

```javascript
const a = 2;
function square(a = a) {
	return a * a;
}	
console.log(square()); // ReferenceError: Cannot access 'a' before initialization at square
```

**참고**

```javascript
const a = 2;
function square(a) {
	return a * a;
}	
console.log(square()); // undefined
```

undefined 이유 : 인수로 undefined → `return undefined * undefined` ⇒ NaN

undefined가 출력안되는 이유 : 명확하게 연산 후. undefined를 반환하기에 NaN이 출력됨

## 3. var, function, import

`var`, `function`, `import`선언은 TDZ에 영향을 받지 않는다. 이것들은 현재 스코프에서 호이스팅 된다.

예3.1 )var 변수는 선언하기 전에 접근하면 undefined를 얻는다

```javascript
value; // undefined
var value;
```

예3.2) 함수는 선언된 위치와 상관없이 동일하게 호출된다

```javascript
greet('World'); // 'Hello, World!'
function greet(who) {
  return `Hello, ${who}!`;
}

greet('Earth'); // 'Hello, Earth!'
```

함수 선언 전에 호출해도 에러가 발생하지 않는 이유는 호이스팅 때문이다.

예3.3) import 모듈도 호이스팅이 가능하다

```javascript
myFunction();
import { myFunction } from './myModule';
```

## 4. TDZ에서 typeof 연산자의 동작

`typeof` 연산자는 변수가 현재 스코프 안에 선언되었는지 확인할 때 유용하다. 

예로 아래의 예시에서 변수 a는 선언되지 않았다. 

```javascript
typeof a; // undefined
```

변수가 선언되지 않았기 때문에 typeof a는 `undefined`로 평가한다

그러나 TDZ의 변수에서 typeof 연산자는 다르게 동작한다.

```javascript
typeof a; // ReferenceError
let a;
```

## 5. 스코프 안에서의 TDZ

> TDZ는 내부 스코프에서만 존재한다.

TDZ는 선언문이 존재하는 **스코프 범위 안**에서 변수에 영향을 준다.

```javascript
// Outer Block Scope
if (outerScope) {
	// Inner Block Scope
	if (innerScope) {
		// Temporal Dead Zone
		variable;
		const variable = 'Hello World';
	}
}
```

예)

```javascript
// Function scope
function doSomething(someVal) {
  typeof variable; // undefined
   // Inner block scope
  if (someVal) {
    typeof variable; // throws `ReferenceError`
    let variable;
  }
}
doSomething(true);
```

위의 예시는 2개의 스코프를 가진다.

- 함수 스코프
- let 변수가 선언된 내부 블록 스코프

`typeof variable` 을 내부 스코프에서 선언하였고, 선언 전에 변수를 사용하면 ReferenceError가 발생한다. TDZ는 내부 스코프에서만 존재한다.

## 결론

TDZ는 const, let, class 구문의 유효성에 영향을 미치는 개념이다.

TDZ는 선언 전에 변수를 사용하면 ReferenceError를 발생시킨다.

var은 호이스팅때문에 변수 선언 전에도 사용가능하기에 var사용은 피해야 한다.

`블럭 스코프, 함수 스코프` - 호이스팅
