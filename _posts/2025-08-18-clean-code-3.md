### 소개

빈약한 도메인, 모델, 객체 : 여러 속성으로 구성되었지만 실질적으로 동작이 결여된 객체

데이터를 외부에 노출하기 위해 getter, setter를 사용하면 객체 자체에 데이터를 보관하지 않고, 외부 소스가 객체 내의 데이터에 접근 + 잠재적으로 수정할 수 있어서 캡슐화 원칙에 위배

### 빈약한 객체를 풍성한 객체로 변환하기

외부 조작으로부터 객체를 보호, 데이터와 구조의 노출 대신에 동작을 노출 해 변경의 영향을 최소화 → 모든 속성을 private로 변환

기존)

```java
public class Song {
	String name;
	String authorName;
	String albumName;
}
```

수정)

```java
public class Song {
	private String name;
	private Artist author;
	private Album album;
	
	public String albumName() {
		return album.name;
	}
}
```

→ Song의 공개된 동작에 의존, 캡슐화를 지향하는 것을 의미

2장에서 정의한 MAPPER에 의하면 객체를 디자인할 때 데이터 모델링하는 빈약한 객체보다는 객체의 동작을 기반으로 객체를 디자인해야 한다.

### 객체의 본질 파악하기

문제 : 객체에서 불변성을 생성하고, 이를 항상 유효하게 유지하고 싶다.

예) 날짜의 월 변경하기

```typescript
const date = new Date();
date.setMonth(4)
```

setMonth()를 호출하면 월의 값만 설정되고, 일/연도의 값은 변경되지 않는다.

날짜에 의존하는 다른 객체는 파급 효과에 의해 변경된다. ⇒ 이전에 생성한 날짜에 결제 기한이 있는 경우, 날짜의 본질을 변경하면 결제 또한 영향을 받게 된다. defer()와 같은 프로토콜을 호출해 해결이 가능하다.

더 나은 옵션은 다음과 같다.

```typescript
const date = new ImmutableDate("2025-08-18");
```

날짜의 본질이 식별되었고, 생성된 이후에는 절대 변경될 일이 없다.

### 객체에서 세터 제거하기

문제 : 세터를 사용한 외부 조작으로부터 객체를 보호하고 불변성을 원한다.

→ 문제 버전

```java
public class Point{
	protected int x;
	protected int y;
	
	public Point() {}
	
	public void setX(int x) {
			this.x = x;		
	}
	public void setY(int y) {
			this.y = y;
	}	
}

Point location = new Point();
location.setX(x);
location.setY(y);
```

→ 수정된 버전

```java
public class Point {
	public Point(int x, int y) {
		this.x = x;
		this.y = y;
	}
}

Point location = new Point(1,2)
```

1. setter메서드는 빈약한 모델을 지향한다. → 예상치 못한 방식으로 변경이 가능해지며, 여러 곳에 불변 무결성을 검증하는 코드를 추가해야 한다.
2. setXXX() 메서드는 현실세계에서 거의 존재하지 않기에 MAPPER원칙에 어긋난다.
3. 객체의 본질을 절대 변경해서는 안되는데 위반한다. → 모든 객체에 파급 효과 방지

### DTO 제거하기

문제 : 레이어 간 완전한 객체를 전송하고 싶다 → 데이터 객체 사용을 피하고 실제 객체를 사용하기.

DTO, 데이터 클래스는 널리 사용되는 빈약한 객체 도구이다. 이 도구는 비즈니스 규칙을 강제하지 않으며, 해당 규칙을 처리하는 로직이 중복되는 경우가 많다.

### 빈 생성자 완성하기

아무런 초기 설정이 없는 빈 생성자가 있다. 이 객체가 항상 완전하고 유효하게 유지되도록 보장하고 싶다.

→ 객체를 생성할 때 모든 필수 인수를 전달하고, 하나의 완전한 단일 생성자 사용하기

예) 빈약하고 일관성이 없는 Person

```java
public Person(); 
```

예) 더 나은 Person 모델

```java
public Person(String name, int age) {
	this.name = name;
	this.age = age;
}
```

→ 본질을 객체에 전달함으로써 변형할 수 없게 한다.

### Getter제거하기

문제 : 객체 접근을 엄격하게 제어하며넛 우발적으로 표시되는 것을 최소화하고, 소프트웨어를 손상하지 않으면서 변경 가능한 유연성을 확보하고 싶다.

```php
final class Window {
	public $width;
	public $height;
	public $children;
	
	public function getWidth() {
		return $this->width;
	}
	public function getArea() {
		return $this->width * $this->height;
	}
	
	public function getChildren() {
		return $this->children;
	}
}
```

→ 수정된 버전

```php
final class Window {
	public $width;
	public $height;
	public $children;
	
	public function width() {
		return $this->width;
	}
	public function area() {
		return $this->width * $this->height;
	}
	
	public function addChildren($aChild) {
		return $this->children[] = $aChild;
	}
}
```

getColor()는 구현형이고 MAPPER에 실제 대응하는 메서드가 없으므로 전단사 규칙을 위반한다.

### 동적 속성 제거하기

문제 : 클래스에서 속성을 선언하지 않고 사용한다. → 속성을 명시적으로 선언하기

```python
class Dream:
	pass

nightmare = Dream()

nightmare.presentation = "dream" // presentation은 정의되지 않음. 동적 속성
```

→ 수정

```python
class Dream:
	def __init__(self):
		self.presentation = ""

nightmare = Dream()
nightmare.presentation = "dream"
```
