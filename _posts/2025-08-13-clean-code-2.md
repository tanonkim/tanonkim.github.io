### 소개

일반적인 소프트웨어의 정의 : 하드웨어의 반대 개념, 컴퓨터가 수행할 작업을 지시하는 명령어

소프트웨어의 구성 : 시스템 작동과 관련된 프로그램, 프로시저(), 루틴(함수)의 모음 (옛날 용어)

`MAPPER` : 소프트웨어는 시뮬레이터를 구축하는 것과 같으며 MAPPER라는 약어로 표현한다.

(Model : Abstract Partial and Programmable Explaning Reality)

### 왜 모델인가

모델은 현실의 특정 측면을 특별한 패러다임을 사용해 구체적인 시간과 관점에 바라본 결과물

소프트웨어 모델의 목표 : 실제 행동을 예측하는 것

### 왜 **`추상적`**인가?

모델은 여러 부품의 모음, 구성 요소의 일부만 보고 완전히 이해할 수 없고, 어떻게 실현해야 하는지 자세히 설명하지 않음

### 왜 프로그래밍이 가능해야 하나?

모델은 시뮬레이터에서 실행할 수 있어야 한다.

### 왜 부분적인가?

관심있는 문제를 모델링하기 위해서는 현실의 일부만 고려해야 한다. 현실 전체를 모델링할 수 없기에 관련 부분만 모델링한다.

### 왜 설명 가능해야 하는가?

모델은 모델링하는 현실에서 행동을 추론하고 예측하는데 도움이 되고, 이에 대한 변화를 관찰할 수 있을만큼 선언적이어야 한다.

### 왜 현실에 관한 것인가?

모델은 관찰 가능한 환경에서 일어나는 상황을 재현해야 한다.

### 규칙 유추하기

소프트웨어 : MAPPER를 따르는 시뮬레이터로 정의한다.

공리 : 증명 없이 명백한 진리로 받아들여지는 진술. 또는 명제

### 유일무이한 소프트웨어 설계 원칙

하나의 규칙에 따라 전체 패러다임을 설계 → 단순하고 우수한 모델을 만들 수 있다.

- 예측 가능성

  소프트웨어 품질 특성 중 가장 과소평가되는 특성

- 모델로 구현하기

  모든 모델을 구축할 때는 실제 세계에서 발생하는 조건을 시물레이션하는 것이 중요하다.

- 전단사의 중요성

  `전단사` : 일대일 함수 == 두 집합의 요소 간에 일대일 대응을 설정하는 함수

  도메인의 모든 요소를 범위의 고유 요소에 매핑하고, 범위의 모든 요소를 도메인 고유 요소로 다시 추적할 수 있음

  `동형(isomorphism)` : 두 수학적 구조를 연결하는 더 강력한 대응 유형

- 모델 생성 시 언어에 미치는 영향

  객체를 단순히 데이터 보유자라고 생각한다면 모델은 전산사 원칙을 잃어버리고 MAPPER원칙을 위반할 것이다.
