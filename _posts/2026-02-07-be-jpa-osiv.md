### OSIV의미

OSIV(Open Session In View)는 영속성 컨텍스트를 뷰까지 열어두는 기능이다.

영속성 컨텍스트가 유지되면 엔티티도 영속 상태로 유지된다. 뷰까지 영속성 컨텍스트가 살아있다면 뷰에서도 지연 로딩을 사용할 수 있다.

참고)

SpringBoot에서는 기본값이 True

JPA에서는 OEIV(Open EntityManager In View), 하이버네이트에선 OSIV(Open Session In View)라고 한다. 하지만 관례상 둘 다 OSIV로 부른다.

![](/assets/img/2026-02-07/be-jpa-osiv-1.png)

영속성 컨텍스트는 **트랜잭션의 생명 주기와 동일**하다.

하지만 OSIV 옵션이 true라면 영속성 컨텍스트의 생명주기를 View에 응답이 갈 때까지 유지시킨다. 기본이 true이기 때문에 따로 설정을 하지 않았다면 Lazy 로딩을 사용했을 때
트랜잭션 범위를 벗어나고 프록시 객체에 접근한다하더라도 `LazyInitializationException`이 발생하지 않는다.

HTTP 요청마다 새로운 데이터베이스 커넥션이 생성이 되는데, DB 커넥션이 많이 발생해서 성능 저하가 발생될 수 있다. (DB 커넥션은 한정적)

OSIV가 true일 경우 API 응답이 끝날때까지 영속성 컨텍스트와 DB 커넥션을 유지하기 때문에 해당 옵션을 고려할 필요가 있다.

### 주의점

영속성 컨텍스트의 생명 주기를 View 응답까지 확장하는거지, 트랜잭션의 생명주기를 확장하는것이 아니다.

영속성 컨텍스트가 유지되는 동안 DB 커넥션은 유지된다. 따라서 트랜잭션 커밋 이후 쓰기작업은 불가하다.

하지만 커넥션은 유지되기에 읽기 작업은 가능하다.

### 장점

지연 로딩은 영속성 컨텍스트가 살아있어야 가능하고, 영속성 컨텍스트는 기본적으로 DB 커넥션을 유지한다. 때문에 **지연로딩을 사용할 때 트랜잭션 범위를 고려하지 않고** 간편하게 코드를 작성할 수 있다.

### 단점

API 호출 동안 커넥션을 반환하지 못하고 **유지**해야 한다. → 너무 오랜 시간 DB 커넥션을 사용할 시 커넥션 부족으로 시스템 장애로 이어질 수 있다.

### OSIV : false일 때

커넥션 리소스를 낭비하지 않는다.

↔

지연로딩은 영속성 컨텍스트가 살아있어야 하는데, 영속성 컨텍스트가 종료되었기에 모든 지연로딩을 트랜잭션 안에서 처리해야 한다. (지연로딩 사용 중일 시 LazyInitializationException 발생 → 트랜잭션 안에서 처리/반환 or fetch join을 사용해서 해결 등 주의)

### 언제 사용해야 할까?

그럼 언제 OSIV를 사용해야 할까?

요청이 많지 않은 간단한 서비스나 커넥션을 많이 사용하지 않은 곳에서는 true

고객 서비스 실시간 API는 false (사내 코드는 open-in-view: false)
