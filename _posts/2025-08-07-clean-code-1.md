### 리팩터링

IDE의 자동화된 리팩토링

시맨틱 리팩토링 → 시스템의 동작을 일부 변경할 수 있어 안정성이 보장되지 않는다.

### 레시피

무언가를 만들거나 변경하기 위한 일련의 지침

### 클린코드

클린코드 : 읽고 이해하고 유지보수하기 쉬운 코드

→ 이를 위해 잘 구조화되고 간결하며, 변수, 함수, 클래스에 의미있는 이름 사용

### 가독성, 성능 혹은 둘 다

성능 - 클린코드 작성 → 테스트 검증 → 파레토 법칙을 활용해 병목 현상을 개선

가독성

### 소프트웨어 유형

이 책의 레시피의 대상 : 복잡한 비즈니스 규칙이 있는 백엔드 시스템

2장부터 레시피는 특정 도메인에 구애받지 않는다.

### 기계 생성 코드

코드를 생성하는 도구가 많아짐에도 클린코드는 필요하다.

### 이 책에서 사용하는 표현

- 메서드 / 함수 / 프로시저
- 속성 / 인스턴스 함수
- 프로토콜 / 행동, 동작 / 인터페이스
- 인자 / 매개변수
- 익명함수 / 클로저 / 람다

### 디자인 패턴

가정 : 객체 지향 디자인에 대한 기본 기념을 이해하고 있다고 가정

### 프로그래밍 언어 패러다임

해당 책에서 제시하는 클린코드 개념은 다양한 프로그래밍 패러다임에 적용 가능하다.

아이디어 중 상당 수는 구조적 프로그래밍과 함수형 프로그래밍에 뿌리를 두고 있다.

일부는 객체지향 세계에서 비롯된 것이다.

### 객체 VS 클래스

레시피 대부분은 클래스가 아닌 객체에 대해 설명한다. (객체의 본질 파악하기)

### 변경성

클린 코드는 소프트웨어가 올바르게 동작하도록 보장 + 유지 관리 및 발전이 용이하도록 한다.
