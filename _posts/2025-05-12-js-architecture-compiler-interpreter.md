## 어셈블리어 : Compile의 역사

> 어셈블리어 : 기계어와 일대일 대응이 되는 컴퓨터 프로그래밍의 저급 언어

컴퓨터 구조에 따라 사용하는 기계어가 달라지며, 기계어에 대응되어 만들어지는 어셈블리어도 각각 다르게 된다.

초기 컴퓨터 프로그램들은 모두 어셈블리어로 작성했다. 그러나 어셈블리어는 컴퓨터 구조에 따라 달라지기에, 새로운 아키텍쳐가 적용된 CPU가 나올 때 마다 매번 같은 프로그램을 CPU에 맞는 어셈블리어로 다시 작성해야 한다.

이 때문에 통일된 언어체계로 작성한 코드의 필요성이 대두되었고, 고급 프로그래밍 언어가 탄생하였다. 하지만 컴퓨터는 고급 언어로 작성한 코드를 바로 인식하지 못하기 때문에 이를 번역할 과정이 필요하고, 이것이 `컴파일`이다.

## 컴파일러와 인터프리터

고급 프로그래밍 언어를 사용하게 되면서 이를 **어셈블리어**로 번역해주는 작업이 시작된다. 번역을 하는 방식에는 두가지가 있고, `컴파일러`와 `인터프리터` 방식이다.

### 컴파일러

대표적 예시) C, C++ JAVA, GO

- 속도

컴파일러는 프로그램 전체를 스캔하여 이를 모두 기계어로 번역한다. 전체를 스캔하기에 컴파일러는 초기 스캔 시간이 오래 걸리는 편이다. 하지만 전체 실행 시간만을 보면 인터프리터보다 빠른데, 컴파일러는 초기 스캔을 마치면 실행 파일을 만들어놓고, 다음에 이전에 만든 실행파일을 실행하기 때문이다.

또한 단순한 변화라도 컴파일 과정이 필요하니, 불편할 수 있다.

- 메모리

컴파일러는 고급언어로 작성된 소스를 기계어로 번역하고, 이 과정에서 **`오브젝트 코드`**라는 파일을 만드는데, 이 오브젝트 코드를 묶어서 하나의 실행파일로 만드는 링킹이라는 작업을 해야 한다. 이 때문에 컴파일러는 일반적으로 인터프리터보다 더 많은 메모리를 사용한다.

- 오류

또한 컴파일러는 오류 메세지를 생성할 때 전체 코드를 검사한 후에 오류 메세지를 생성한다. 그래서 실행 전에 오류를 발견할 수 있다.

---

### 인터프리터

대표적 예시) Javascript, Python

- 속도

컴파일러와는 반대로 인터프리터는 프로그램 실행 시 한 번에 한 문장씩 번역한다. 그렇기 때문에 전체를 스캔하고 오브젝트 코드를 실행하는 컴파일러보다 실행시간이 더 걸린다.

- 메모리

하지만 인터프리터는 메모리 효율이 좋다. 왜냐하면 컴파일러처럼 오브젝트 코드를 생성하지 않고, 링킹 과정도 거치지 않기 때문이다. 이 때문에 인터프리터는 메로리 사용에 있어 컴파일러보다 효율적인 모습을 보인다.

- 오류

인터프리터는 한 번에 한 문장씩 번역하기 때문에 프로그램을 실행시키고 한 문장씩 번역될 때 오류를 만나게 되면 프로그램을 중지한다. 그래서 프로그램을 실행해봐야지만 오류 발견이 가능하다.

## 런타임

런타임은 프로그램의 실행이 시작되어 종료될 때까지의 시간동안 **프로그램이 동작하는 모든 단계와 상황**을 말한다. (이는 컴파일 단계에서 생성된 기계어나 중간 바이트 코드가 실제로 실행되는 시간을 가리킨다.)

컴퓨터 산업 초기에는 컴퓨터 시스템이 명령어를 처리하는 과정 자체가 비교적 짧았기 때문에 런타임이라는 개념은 크게 강조되지 않았다. 그러나 프로그래밍 언어가 복잡해지고, 프로그램이 더 다양한 작업을 수행하게 되면서 프로그램 실행 도중의 동작과 문제해결이 더욱 중요해지게 되었다.

### 컴파일 타임 에러와 런타임 에러

컴파일타임 에러라고 하면 컴파일을 하는 과정에서 문제가 생긴 것이다. 즉 번역이 안된다는 것이다.

컴파일러에 문제가 없다고 가정한다면 번역할 소스코드가 잘못 적힌 경우이다. Syntax Error, Type Check Error가 바로 컴파일타임 에러의 대표적인 예시이다.

런타임 에러는 실행프로그램까지는 완성되었지만, 실행하는 과정에서 문제가 생긴 것이다. 소스코드를 해석하는 것 자체는 가능했지만, 실행할 수 없는 환경이다. Divide By Zero, 메모리 부족 등이 있다.
